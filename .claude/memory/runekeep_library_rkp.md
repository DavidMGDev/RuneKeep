**v0.10.0 (2026-06-23, PR #337)** added an app-level **Card Library** + the **`.rkp`** file format. This is SEPARATE from per-character sheet cards. See [[runekeep_apk_build]], [[runekeep_card_types]], [[project_runekeep_overview]].

**Pure modules (unit-tested):**
- `src/lib/rkp.ts` — one JSON envelope `{ format:'rkp', rkpVersion, kind, payload }`; `kind` ∈ `character | card | expansion`. `serializeRkp`/`parseRkp`/`rkpKind`. Character payload routes through `parseCharacterFile`. Content-based parse — a renamed file still works. The single import trust boundary.
- `src/lib/library.ts` — `Expansion` (id immutable across versions, `version` int monotonic, `cards: LibraryCard[]`) + `LibraryCard` (`contentType` ∈ ancestry|community|domain|subclass|class|generic; domain+level; className; `ancestryEffectTrait` 1|2 for mixed cross-out). `mergeDecision(existing,incoming)` → add|update|skip|same (by version). `contentForCreation(enabled)` buckets by type. `validateExpansion`. `.rkp` uses `application/octet-stream` MIME (no registered MIME for .rkp); import picker uses `type:'*/*'` then validates by content.
- `src/lib/library-store.ts` — one JSON per expansion under `documents/library/` (mirrors character-store; web localStorage shim `runekeep.library`). `exportRkp`/`importExpansionRkp` (update-in-place by version) via expo-sharing + expo-document-picker.

**UI:** main menu **Cards → `/library`** (`src/app/library.tsx` → `src/features/library/library-screen.tsx`). Hub: archive link (→ `/gallery`) + expansion list. Expansion detail: author/edit/delete cards (reuses `CardEditor` with an `extraField` = content-type config), edit metadata (name/author/description/version stepper), Share, Delete. Character export/import switched to `.rkp` (`character-store.ts` `readCharacterText` still accepts legacy bare `.runekeep.json`). NOTE: `/library` was cast `as Href` in menu-screen because expo typedRoutes' generated `.expo/types/router.d.ts` was stale for the new route (regenerates on prebuild/dev).

**NFC tap-to-share — SHIPPED v0.10.1 (PR #339, 2026-06-23).** Phone-to-phone via **Host Card Emulation** (Android Beam is dead since Android 10): sender HCE-emulates an NFC Type-4 NDEF tag carrying a serialized `.rkp` (`react-native-hce` 0.3.0), receiver reads it as NDEF (`react-native-nfc-manager` 3.17.2). APK-ONLY — both native modules are absent from Expo Go, so `nfcModulesPresent()` (Platform+try/catch lazy-require) gates all NFC UI off in Expo Go/iOS. `src/lib/nfc.ts` (startNfcSend/receiveNfc/nfcModulesPresent, 64KB Type-4 ceiling warned), `src/features/share/nfc-modal.tsx` (send/receive UI). Entry points: Library expansion **NFC**/hub **Receive NFC** (version-aware; single card → "Received cards" expansion); Golden Gear Edit **Send NFC** (sheet card → LibraryCard converter via findEditableCard/effectsForCardId). **`plugins/withNfcHce.js`** = local Expo config plugin (in app.json as `"./plugins/withNfcHce"`) injecting the HCE `CardService` + `res/xml/aid_list.xml` (AID `D2760000850101` = NFC Forum Type-4 well-known) + `nfc.hce` uses-feature (required=FALSE so non-NFC phones still install); NFC permission via nfc-manager's own plugin (`["react-native-nfc-manager",{nfcPermission}]`). **Verified: compiles into the release APK (78.6 MB); manifest injection confirmed via prebuild. The actual back-to-back TAP is owner-verified on device** (couldn't be tested by the agent). nfc-manager's prebuild warning "withBuildScriptExtVersion: Cannot set ... compileSdkVersion" is NON-FATAL (Expo already sets compileSdk 36). Installed with `--legacy-peer-deps`. GOTCHA: `npm install <native dep>` then `git checkout -- package.json` (to undo prebuild's script flip) ALSO strips the new dep lines if they weren't committed yet — commit deps first, or re-add.

**v0.10.2 (PR #340, 2026-07-14) — authoring overhaul + NFC trim + leveling fixes.** Custom-card editor is now **content-type-FIRST** (`TypeChooser` in library-screen) and the single body box became **add/del/reorder `sections[]`** with a Bold/Italic/bullet toolbar (`SectionsField` in `components/card-editor.tsx`, OPT-IN via the `sectioned` prop so experiences/notes/sheet cards are unchanged; `composeSections` is pure in `lib/card-markdown.ts` + unit-tested). New content types **weapon/armor/inventory + custom-typed**; `LibraryCard` gained `sections`/`weapon: WeaponSpec`/`armor: ArmorSpec` (def-shaped, mechanical) and `contentForCreation` now buckets weapons/armor/inventory. Ancestry = 2 fixed feature sections + `ancestryEffectTrait`. **NFC trimmed to single-card only** (dropped whole-expansion + multi-card send; per-card send in the library; Golden Gear Send NFC = exactly 1 card; receive rejects non-card). Also: per-tier advancement reset (`advancementMarksTier` self-heals stuck saves) + subclass upgrade auto-adds the next card ([[runekeep_apk_build]]); Class cards now show in the Card Archive; per-section Random + Skip cards in creation; in-creation custom-inventory authoring REMOVED.

**B4 SHIPPED — v0.10.3 (PR #341, 2026-07-14) — custom content in creation + ADD GEAR (Feature 7 / Bug 1 / Bug 4).** The KEY IDEA: **embed, don't reference.** A picked homebrew card is stored as a self-contained COPY on **`CharacterFile.libraryCards`** (new field), so a hero renders + resolves effects with NO expansion installed and survives it being disabled/deleted. **INVARIANT (unit-tested): no `libraryCards` = byte-identical load + render.** Pieces: `src/lib/library-embed.ts` (pure: `libraryCardById/Body/Effects`, `armorSpecEffects` bakes custom armor score+thresholds like equipment); `parseCharacterFile` accepts structural/domain ids backed by `libraryCards` (+ normalizes via the shared `normalizeLibraryCard` — extracted from validateExpansion); `toSheetCharacter` + `card-effects` (`effectsForCardId`/`sourceLabelForCardId`) resolve embedded cards. **Sheet:** the forge-jobs memo forges each `libraryCard` (`libJobs`); the deck-assembly memo resolves the structural trio + domains **catalog-first THEN embedded** via `catItem`/`libItem` (so a custom card sits in its OWN slot → origin badges + order intact) and places loose ones (weapon/armor/inventory/generic) in inventory (`looseLibItems`). **Creation:** `contentForCreation(enabled)` appended to ancestry/community/subclass/domains/armor/inventory decks; `forge()` embeds picks (`draft.inventoryLibIds` for loose inventory) + auto-enables armor/effect cards. **Library:** per-expansion `enabled?` flag + `isExpansionEnabled`/`setExpansionEnabled` toggle (NON-destructive — only hides from creation/gear). **ADD GEAR:** `GearBrowser` "Homebrew" tab + `onAcquireCustom` embeds a fresh-id copy. **v0.10.4 (PR #342, 2026-07-15): mixed-CUSTOM-ancestry cross-out now WORKS** — added `~~strike~~` to `lib/card-markdown` (MdSpan.strike → line-through+dim); `libraryCardBody(lc, struckIndex)` wraps the crossed feature; `mixedCrossedTrait(file,id)` (first-picked keeps feature 1 → strikes 2; second keeps 2 → strikes 1) drives BOTH the render (redesigned-sheet `libJobs`) AND the passive-disable (`card-effects` effectsForCardId). Also fixed the level-up **Confirm button** (owner: "always disabled, can't level any character"): the leveling LOGIC was already correct (diagnostic proved advancements + domain options available) — the real bug was a SILENT disabled button when a step was incomplete (every new char's 1st level-up is a tier start → needs an Experience). Now the button is always actionable: names the missing requirement + jumps to that step (`level-up-panel.tsx` `missing`). STILL DEFERRED after v0.10.4: custom EQUIPPED weapons + custom standalone CLASSES. tsc clean + 288 tests.

**v0.10.5 (PR #343, 2026-07-15): subclass upgrade cards + level cap + custom 3-TIER subclasses.** (1) The subclass-upgrade advancement's added card (Bug 3) now rides the **Arsenal** (`applyLevelUp` sets `cardCategory[nextId]='abilities'`) instead of Inventory — it looked "not added" because it was buried in inventory; `parseCharacterFile` backfill routes existing saves too. (2) `nextSubclassCardId(file, foundationId, tier)` is now **file-aware** — resolves catalog families AND custom ones via `file.libraryCards` matched by shared `subclass` family + `className`. (3) **Custom subclasses = 3 tier cards**: `LibraryCard` gained `subclass` (family) + `tier` (1|2|3); the library Subclass editor has a Foundation/Specialization/Mastery selector + family name; creation offers only the FOUNDATION (tier 1) and embeds its spec+mastery siblings (hidden on the sheet via `looseLibItems` filter until the upgrade acquires them). (4) **Level 10 is the cap** (`MAX_LEVEL=10`): `applyLevelUp` is a no-op at 10; the panel shows a "Max level" message (was letting you reach 11). STILL DEFERRED: custom EQUIPPED weapons ([[runekeep_no_digital_dice]] — weaponById + damage calculator, NOT any roll) + custom standalone CLASSES (undesigned chassis). tsc clean + 291 tests.
