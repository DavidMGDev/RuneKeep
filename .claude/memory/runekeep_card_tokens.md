Fullscreen cards can be decorated with cosmetic "sewing button" **tokens** (PRD #244, PR #245, app **v0.2.5**, shipped 2026-06-15). Tokens are PURELY decorative — never read by the modifier engine (#175), so they don't re-derive `character`, only persist. See [[runekeep_card_categories]], [[runekeep_modifier_system]], [[runekeep_apk_build]], [[project_runekeep_overview]].

**Where:** the token board shows over any **fullscreen** card — the carousel focus AND the origin-card preview (`origin-card-preview.tsx`, the Subclass/Ancestry/Community badges, #242). A drawer **tab** fades in at the top (opacity tied to `fullscreenProgress`); tap to open the tray, drag the tab horizontally to reposition (persisted `tokenDrawerX`).

**Modules:**
- `components/card-tokens-data.ts` — PURE (no RN/SVG): `TokenKind` = `wood|bone|iron|color`, `PlacedToken {id,kind,color?,x,y}` (x/y normalized [0,1] to the card rect = token CENTER), `TOKEN_BASE`/`DEFAULT_TOKEN_KINDS`/`TOKEN_COLORS`/`TOKEN_FRAC` (0.17), `tokenFill`, `pickTokenColor(prev,rnd)` (deterministic, never returns prev), `randomTokenColor`, `hashStr`. Unit-tested in `card-tokens-data.test.ts` (kept RN-free so the test stays pure; the .tsx re-exports it via `export *`).
- `components/card-tokens.tsx` — visuals: `TokenButton` (HD SVG: rim + radial-gradient face + 4 holes + drop shadow) and `BakedTokenLayer` → cheap **plain-View** `LodToken` discs (NO svg/gradient/shadow) so the whole deck's baked tokens cost almost nothing.
- `components/card-token-board.tsx` — the interactive surface `TokenBoard({cardRect,width,height,tokens,drawerColor,drawerX,scale,...})` + the `CarouselTokenBoard` wrapper. `scale` converts a gesture's screen-px translation → parent-px (the carousel board lives inside the scaled `DesignStage`; the origin preview is screen-space, scale 1).

**Interactions:** drag a drawer source onto the card → place a token at the normalized drop point (clamped [0,1] so a half-off drop sits on the edge; a drop off-card springs back). The **colour** source: TAP cycles a random colour (Exclusive(pan,tap)) persisted as `tokenColor` across ALL cards; DRAG places a token frozen at that colour. A placed token: HOLD (fullscreen only) → grow + spark build-up then DROP off the card under gravity (`FallingToken`, mirrors heart-track but falls instead of exploding; drift/spin from `hashStr(id)`, no Math.random in worklets); TAP with the drawer OPEN → eyedrop its colour into the drawer button. Placed tokens CANNOT be moved (#244 item 8). Stacking allowed (no collision).

**Architecture decisions:**
- `DesignStage` now publishes its uniform `scale` via `StageScaleContext`/`useStageScale()` (design-stage.tsx) so in-stage gesture math is device-accurate (the old carousel just approximated with PAN_R).
- `CarouselTokenBoard` is a SIBLING of `CardCarousel` inside `DesignStage` (NOT nested under the carousel pan) so token gestures never fight the scroll. zIndex 3600 (above the focused card 3000 + the Modifiers button 3500), `box-none` so taps off the tokens/drawer still close the card. Mounted only while focused (`fullscreenProgress>0.5 && switching!==1 && machineState==='fullscreen'`) → returns null otherwise (no stray hit-testing).
- carousel-context threads `cardTokens`/`tokenColor`/`tokenDrawerX` + `placeToken`/`removeToken`/`setTokenColor`/`moveTokenDrawer`; the SLOT renders `BakedTokenLayer` next to `EnabledCorner` (so tokens ride rise/switch transitions, visible like the enabled triangle) but HIDES it on the focused card (`tokenFade` → board takes over; a drop never doubles with a static LOD twin — `beginDrop` calls onRemove immediately while the board animates the fall).
- Baked-vs-board geometry is EXACT: focused cardRect = center (OX=206, FS_CENTER_Y=420), size CARD_W·FS_FOCUS_SCALE × CARD_H·FS_FOCUS_SCALE — a token at normalized (x,y) lands at the same screen spot in both layers.
- Origin preview MEASURES the card's real on-screen box (it isn't screen-centered — the Equip/Close controls sit below it) and anchors a screen-space `TokenBoard` (scale 1) to it.
- `DraggableSource` renders at LOCAL coords inside the tray but carries ABSOLUTE `homeX/homeY` for the drop test (the tray origin is `drawerLeft,trayTop` — don't double-offset).

**Schema (additive, `schemaVersion` STAYS 1):** `cardTokens?: Record<cardId, PlacedToken[]>`, `tokenColor?: string`, `tokenDrawerX?: number` on `CharacterFile`. Old saves (undefined) just have no tokens.

**v0.2.6 fixes (#246, PR #247):** the v0.2.5 tokens shipped with TWO crashes — (1) the drop animation used RN `rotate:'turn'` (RN transforms accept only deg/rad → native crash); fixed to `deg`. (2) eyedrop tap called `tokenFill(token)` INSIDE a worklet (`Gesture.Tap().onEnd('worklet')`) → "non-worklet function" crash; fixed by computing `fill` on JS in render and passing the string into the worklet. **GOTCHA (general):** never call a plain JS helper inside a `'worklet'`; precompute on JS + capture the primitive. **Visual:** dropped the flat plain-View LOD + native `elevation`; now ONE shared bevelled SVG `TokenButton` (gradient + an in-SVG soft-shadow ellipse, no platform shadow) used by BOTH the baked deck layer and the board — identical near/far (it just scales = its own LOD), and no flat→HD swap so no lag/pop. `kindScale(kind)`: wood 0.8 / bone 1.0 / iron 1.2 / color 1.0 (applied to baked + drawer + placed). Board + Modifiers button now FADE in (mount at `fullscreenProgress>0.02`) instead of popping at a 0.5 threshold.

**v0.2.7 (#248):** token tab no longer renders under the status bar on the origin-card preview — `TokenBoard` gained a `drawerTop` prop (default 6); the screen-space origin preview passes `Math.max(insets.top,24)+16`; the in-stage carousel board keeps 6 (already inset by the DesignStage). Token FADE across the fullscreen fly was tuned to avoid the jump: the baked layer (slot `tokenFade`) fades OUT over the first quarter of `fullscreenProgress`.

**v0.2.8 (#250):** the board fade is now SETTLE-GATED, not progress-interpolated (the spring overshoot meant `progress>0.75` still had the card moving). `CarouselTokenBoard` uses a `useAnimatedReaction` on `fullscreenProgress`: when it crosses >0.99 it arms `ready = withDelay(380, withTiming(1,200))`; if it drops below 0.99 it cancels + resets to 0. `fade.opacity = ready.value`. So tokens appear ~380ms after the card has fully arrived (owner: "I don't care if late, just make sure it stopped moving").

**v0.5 — die tokens + drawer redesign (#293, PR #295, shipped 2026-06-16):**
- **Drawer redesigned to 3 fixed panels.** Closed = ONE centered "open" button (no drag-tab, no close button — the drawer closes only when the card leaves fullscreen and the board unmounts). Open reveals three aligned top panels: card action edit/delete (LEFT, hidden for beastform), token sources wood/bone/iron/colour (CENTRE, unchanged behaviour), die source (RIGHT). Drag-to-reposition removed → `tokenDrawerX`/`moveTokenDrawer`/`onMoveDrawer` are now DEAD for the carousel board (still in carousel-context, unused by the new `TokenBoard`; origin-card-preview dropped them too). The always-on corner action button was MOVED into the left panel (`canAct`/`editable`/`onEditCard`/`onRequestDelete` props on `TokenBoard`).
- **Die = a new token kind reusing the whole system.** `TokenKind` gained `'die'`; `PlacedToken` gained `dieType?: DieType` (`d4|d6|d8|d10|d12|d20`) + `dieValue?`. Data: `DIE_TYPES`/`DIE_MAX`/`DIE_COLOR` (d4 red, d6 orange, **d8 violet #8A6FC4** — was illegible light gold), `nextDieType`/`nextDieValue` (wrapping), `dieGeometry(type)` (builds each die as a regular n-gon, uniformly scaled + translated so its bbox is CENTRED at (62,62), number on the centroid — a test asserts the centering; this fixed the owner's "dice not centred / numbers off" complaints), `dieNumberFrac(type)` (d6/d8/d10/d12/d20 share ONE digit size; d4 smaller for the triangle) + `dieNumberOffset` (d4 nudged left 3 / up 6 box-units). Visuals: `DieButton` (shadow=silhouette translated down, rim, gradient face, number as RN `<Text>` — SVG `<text>`/dominant-baseline is unreliable on RN AND in resvg) + `TokenGlyph({size,token})` dispatch (die→DieButton else TokenButton) used by `BakedTokenLayer`, `FallingToken`, `PlacedTokenView`, `DraggableSource`.
- **Interactions:** source die TAP cycles TYPE (Exclusive(pan,tap), like the colour source) + DRAG places; placed die TAP cycles VALUE 1..max (`updateToken` → patches the matching token in `file.cardTokens[cardId]`; new context method `updateToken`/`onUpdateToken` + sheet handler, mirrors removeToken), HOLD removes (same fall animation).
- **Schema (still additive, `schemaVersion` STAYS 1):** `dieType?`/`dieValue?` on `PlacedToken`.
- **Preview tooling (mine, DELETED before publish):** `_die_preview2.mjs` (resvg renders the beveled shapes) + `_die_numbers.py` (Pillow draws numbers at exact centroids via `textbbox`) → `assets/temp/die-preview/`. Lesson: verify centering by MEASURING the PNG with PIL (bbox of non-bg pixels vs cell centre), don't eyeball — the owner caught two misalignments I'd approved by eye.

**v0.6 — drawer polish, 2× dice, perf (#297, PRs #298/#299, shipped 2026-06-16):**
- **Action button = single outline.** The left edit/delete panel IS the button now (a `Pressable` styled `panelBox` with a centred `ActionIcon` Svg) — the old inner bordered box (`CardActionButton`) is gone. Left + right (die) panels EXPAND horizontally to fill the row (`sideW = max(SIDE_GLYPH+2·PAD, (width−2·SIDE−CENTER_W−2·GAP)/2)`); `PANEL_H` 56→60; side glyphs bigger (`SIDE_GLYPH=48`); centre tokens unchanged. `DraggableSource` gained a `base` prop (die source passes `base=48`). `LEFT_W`/`RIGHT_W` removed.
- **Placed dice 2×, start at 1.** New `DIE_PLACED_MULT=2` + `placedKindScale(kind)` (= `kindScale·2` for die, else `kindScale`) used by the board's placed/falling tokens AND `BakedTokenLayer` (the drawer SOURCE still uses `kindScale`, so it's unchanged). A dropped die sets `dieValue=1` (source still shows `DIE_MAX`).
- **Float-menu perf fix (UNVERIFIED on device).** Three levers: `cardTokens` memo keyed on `file?.cardTokens` not `[file]` (unrelated edits stopped churning the carousel context); `TokenGlyph` memoised; the slot's `BakedTokenLayer` now gated to the full-res window (`withImage && tokens.length`) so far thumbs don't composite gradient SVGs under the float-menu dim. If still bad on device, next lever = a cheap FLAT baked-token LOD (regresses the bevelled look on far cards). Side effect: tokens no longer draw on far-edge thumbs.
- **Origin preview is now multi-page** (`origin-card-preview.tsx` takes `pages: OriginPage[]`, not `source`): subclass→[subclass, ...class-feature faces from the `features-<class>` deck item], mixed ancestry→both cards with per-line `TraitCrossOut` (first crosses trait 2, second trait 1). Tap left/right half to page; page dots in their own row clear of Equip/Close; `borderRadius` removed (no card has rounded corners). Token board only on page 0; equip stays bound to the primary id. Built in `redesigned-sheet` `onOpenOrigin`.
