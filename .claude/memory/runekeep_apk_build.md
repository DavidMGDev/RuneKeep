RuneKeep ships an offline Android APK (all card data bundled, no DB — fits under 90MB). Build + optimization landed on `main` via PR #173 (2026-06-13). See [[runekeep_dev_pipeline]], [[project_runekeep_overview]].

**Build it (npm front-door since refactor #300/PR#301):** FIRST `npm run prebuild:android` (= `expo prebuild -p android --no-install`; regenerates gitignored `android/`; then `git checkout -- package.json` to revert the run:* script flip; the `sharp-cli` warning is non-fatal), THEN `npm run build:apk` (= `powershell -ExecutionPolicy Bypass -File apk-build/build-apk.ps1`; the script is now portable via `$PSScriptRoot` and bumps version from a single `$ver` var). See [[runekeep-maintainability-refactor]]. Produces an **arm64-v8a** release APK (covers the owner's A54 + modern phones), minify + resource-shrink on, **debug-signed** (sideload); the script copies it to **`Runekeep v0.2.apk`** (owner wants the asset named "Runekeep vX.X") and publishes a `gh release`. First run ~15-25 min (Gradle + native compile); re-runs fast.

**GOTCHA (v0.10.7 — background 10-min timeout vs. lingering Gradle daemons):** the agent's background build tool caps a single command at **600000ms (10 min)**. A normal warm/cached build is ~2 min, BUT if a prior build was KILLED (e.g. hit the cap), its **Gradle daemon (java.exe) lingers and contends** — the next run started ANOTHER cold daemon and crawled, getting killed at 10 min again (looked like a "build failure" but was pure daemon contention; it had reached `:app:minifyReleaseWithR8`, near done). FIX: before re-running, kill ALL stale java daemons — `Get-Process java | ForEach-Object { Stop-Process -Id $_.Id -Force }` (also kill any `build-apk.ps1` shell matched by `CommandLine -match 'build-apk\.ps1'`) — then re-run; it completed in **1m48s** clean. So: a build "killed" at ~10 min is usually NOT a code failure — clear daemons and retry. (Don't confuse the false-positive where a `Get-CimInstance ... -like '*build-apk*'` query matches its OWN command line.)
