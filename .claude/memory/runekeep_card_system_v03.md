Architecture from the **v0.3** batch (PRs #266/267/268/270/271/272/273/274). See [[runekeep_apk_build]], [[runekeep_modifier_system]], [[runekeep_card_categories]].

**Duplicate-card instance ids (#269/PR #270) — RESPECT THIS in all future card work:** a player can hold several copies of one catalog card (equipped + acquired, or "Add another copy" in the gear browser — `acquiredCardIds` is now a multiset, the old de-dupe guard was removed). The deck-derivation memo in `redesigned-sheet.tsx` runs `dedupeIds()` (`card-data.ts`) over all deck items: the FIRST occurrence of an id keeps the catalog id (back-compat with saved tokens/category/enable/order keyed by it), repeats get `id#2`, `id#3`. **Interaction already keys by `item.id`, so each copy is independently selectable/draggable/tokenable with NO interaction-code changes.** Content/effects resolve by catalog id: `catalogIdOf(id)` (`card-effects.ts`) strips a trailing `#\d+`. **SUPERSEDED in v0.4 (#277):** effects now resolve via `refOf(id, file)` (a copy's `ref`, else `catalogIdOf`), and ENABLE + effects key by **ref** — so duplicate copies SHARE one equip and apply their effect **ONCE** (v0.3's "once per copy" was reversed). `onDeleteCards` is duplicate-aware: removes ONE acquired copy (count-based), hides non-acquired instances by id. **Ceiling:** positional ids — reordering two IDENTICAL copies can swap their per-instance state (non-corrupting; same card).

**v0.4 card-system additions (PRs #280/281/283/284/285/286/287/288/290):**

Each copy = an individual instance (own position/category/tokens, by instance id) referencing an underlying card; enable + effects key by `ref` (`refOf`), so copies share an equip and apply once (`enabledCardIds` now holds REFS; `toSheetCharacter` dedupes). Gallery "Duplicate" button (`onDuplicateCards`). The carousel enabled-corner + Modifiers-panel `enabled` check by `card.ref`/`refOf`.
- **Formula effects + writable Modifiers panel (#278):** `CardEffect.dynamic:'formula'` + `formula {variable: level|tier|proficiency|trait, multiply?, divide?}` → `ceil(var*mul/div)` in the dynamic pass (round UP). Shared `src/components/effects-editor.tsx` (`EffectsField`+`EffectPicker`, ƒx advanced mode) used by the card dialog AND `CardModifiersSheet` (now read+write via a pencil). Per-card override `CharacterFile.cardEffectOverrides` (catalog id → effects) lets users edit catalog cards; custom cards edit their own `.effects`. `effectsForCardId` resolves override → custom → catalog.
- **Beastform rework (#279):** `onToggleCard` transforms on enabling a wildshape — auto-unequips weapon-type cards (`beastformUnequipped`, restored on exit), snapshots enabled domains (`beastformDomainSnapshot`), blocks switching forms / new weapons / new domains while transformed (plays `floatMenuClose`), 0-HP auto-exit (reactive `useEffect` on `character.hp`). - **Ancestry cross-out (#276 item 3):** per-line strike positions are OWNER-MEASURED via a marking tool (`assets/temp/ancestry-marker/mark.html` → `ancestry-strikes.json`), stored in `ancestry-trait-regions.ts` `ANCESTRY_STRIKES {a:lines, b:lines}`; `TraitCrossOut` draws BLACK strikes per line, x 0.065–0.935. **Mixed ancestry (#265, 3 slices #272/273/274):** combine two ancestries — `first` keeps its 1st trait, `second` keeps its 2nd; the other half is crossed out and its modifiers dropped. Schema: additive `CharacterFile.mixedAncestry { first, second }` (when set, `ancestryCardId` = first for the name; second rides along via `acquiredCardIds`). `ancestry-traits.ts`: `ANCESTRY_EFFECT_TRAIT` tags which trait owns each modifier-bearing ancestry's passive (Giant/Human/Galapa → trait 1, Simiah → trait 2; the only 4 ancestries with passives); `isAncestryEffectDisabled` is applied in `effectsForCardId` so a mixed-in Giant taken for its 2nd trait grants no +1 Max HP. Cross-out visual: `TraitCrossOut` overlay (`character-sheet/components/`) — modeled on `EnabledCorner`, a sibling at the card's authoring size so it RIDES the slot transform (owner requirement: must follow the card, not a fixed overlay). Fed by a `crossOuts: Record<cardId,1|2>` map threaded through `carousel-context` (sheet) and a `crossOuts` prop on `straight-carousel` (creation). Strike bands come from `ancestry-trait-regions.ts` `ANCESTRY_SPLIT_Y` — per-card normalized split between trait 1/2, **estimated proportionally from each card's feature-1 text length** (the baked webp art has no runtime geometry), TUNABLE by eye on device. Creation UI (`create-screen.tsx`): a "Mixed Ancestry" card at the end of the ancestry carousel enters mixed mode (fade transition via a container-level opacity dip, not a per-slot rewrite); ordered two-pick with deselect (a card can't fill both slots → same-ancestry mix impossible); "Single Ancestry" card reverts.

**Custom-card EDITOR (#264 item 5/PR #268):** `CardEditor` already accepted an unused `initial?: CardDraft` — editing = render it pre-filled, `saveLabel="Save changes"`, no catalog button. `EditCardFlow` (`character-sheet/redesign/`) wraps it; `findEditableCard`/`isEditableCard`/`editableCardIds` (`card-effects.ts`) decide custom (editable) vs catalog. Reachable from the gallery (single-select → Edit button) AND fullscreen in the carousel: `CarouselTokenBoard` hosts a top-left action by the token drawer tab — pencil (edit) for custom, trash (delete) for catalog — and `closeFullscreen()`s before opening so the carousel never desyncs. `HoldToConfirm` (`src/components/`) is the damage-panel hold gesture (rising charge fill) extracted for the editor's "hold to delete" + the catalog delete confirm.

**Card markdown (#264 item 6/PR #267):** `src/lib/card-markdown.ts` is a tiny hand-rolled parser (no dependency — a full md lib fights the fontSize-9 card layout): **bold**/*italic*/`_`/bullet/numbered lists, DESCRIPTIONS only (not titles). `CardMarkdownBody` (`src/components/`) keeps the autosizing single `<Text>` for plain/inline-only (zero regression) and uses block layout only when lists appear; wired into `ForgedCard` body.
