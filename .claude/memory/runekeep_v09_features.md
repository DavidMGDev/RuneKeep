## v0.9.7 patch (PR #334) — persistence + control fixes

- **In-play state now PERSISTS** (the big owner bug: HP/Stress/Hope/Armor/Gold reset to full on every app open). Root cause: `toSheetCharacter` (character-file.ts) HARD-CODED current resources to full/default (`hp: maxHp`, `stress.active: 0`, `hope.active: 2`, `armor.active: armorMax`); Gold was read from `file.gold` but the +/- only `setCharacter`'d, never wrote back. Fix: new **additive `CharacterFile.resources` = {hp, stress, hope, armor}** (gold stays its own field); `toSheetCharacter` rehydrates them via `clampRes(n,max)` (absent → old full/default behavior). In redesigned-sheet, a stable **`saveFileRef.current`** (a ref, NOT useCallback — so the ~16 save call-sites don't each need it as a dep) STAMPS the live resource snapshot (`liveResRef`, refreshed every render from `character`) onto EVERY disk write; ALL `saveCharacter(next)` calls were routed through it. Resource-only changes (no file edit) persist via a **debounced effect (450ms)** keyed on `character.hp/stress.active/hope.active/armor.active/gold`, **flushed on AppState≠active + unmount**. Resources are kept OUT of `file` STATE on purpose — so a pip/gold change never re-derives the carousel memo. Portrait already persisted (`onPortraitReplace`→`mutateFile`); this only added the resource path. Tested: `character-file.test.ts` resource round-trip + clamp.
- **Float menu closes on off-target tap** (float-menu.tsx `pickWedge`): was angle-ONLY (`atan2` → nearest sector), so a tap/release ANYWHERE snapped to a wedge and opened it. Added a **radius gate**: `dist = hypot(dx,dy); if (dist < DEAD || dist > ROUT) return -1`. Now outside the wedge ring (ROUT=205 design px) → close; inside a wedge → open it (whole wedge, not just the icon). Gates BOTH the drag-release path and the pinned tap-scrim (both call pickWedge).
- **Gold hold-to-bulk** (gold-card.tsx): `Step` converted from `onPress` to **`onPressIn`/`onPressOut` auto-repeat** that accelerates (delay 360ms ×0.8 → floor 60ms); `onStep` returns false at ceiling/floor to self-stop; a quick tap = exactly one step. The repeat COMPOUNDS via `goldRef` (the `gold` prop is stale inside the timer). Scoped to the Gold card's Step only (other steppers unchanged).
- **Gear-add audit + toast**: the deck-builder override pass now falls back to the **catalog-id (ref) override** — `override[it.id] ?? override[catalogIdOf(it.id)]` (base) and `override[copy.id] ?? override[copy.ref]` (copies) — so a duplicate `#N` instance (the dedupeIds rename) inherits the chosen category instead of the default deck (fixes "weapons sometimes land in the wrong category"). `onAcquireCard` now validates the id resolves (cardById/weaponById/armorById/lootById/class-) → "Couldn't add that card" notice; blocks an id already held as STARTING equipment (the deck builder drops it → would silently vanish) → "Already equipped — not added"; and on success pushes a **"Added to {categoryLabel}"** confirmation. Reads `fileRef.current` for validation + calls `pushNotice` OUTSIDE the `setFile` updater (no render-phase setState).

## v0.9.5 patch (#328, PR #329) — MERGED but NOT yet published as an APK (owner said "stop here")
- **Armor Score animates like HP** (redesigned-sheet.tsx card-toggle handler): gaining Armor Score now fills the new armor slots all at once (shields fly IN), and unequipping bursts the lost score OUT — exactly like Max HP fills/breaks hearts. The fix is a one-line MIRROR of the existing `hpGain` pattern: `const armorGain = Math.max(0, d.armorScore - c.armorScore); armor.active = Math.min(d.armorScore, c.armor.active + armorGain)`. The animation rides the ALREADY-WIRED `burstResources` → `armorRef.current?.burst(prev.armor.active, next.armor.active)`; before this, `armor.active` was clamped to the OLD value so the burst had no delta and new slots showed empty. **Sound is identical to HP by construction** — the equip/unequip burst is a SILENT visual path for BOTH (HeartTrack/ChargeTrack `.burst()` play no sfx; only gesture/keypad paths do). Empty/locked-only transitions stay silent for both (no animating an already-empty heart/shield). **Stress & Hope are intentionally EXCLUDED** — only HP + Armor Score follow-the-gain. RULE for future work: don't add an equip-burst sound to armor, and don't extend follow-the-gain to stress/hope. See [[runekeep_apk_build]].

## v0.9.4 patch (PRs #325/#326/#327)
- **Damage thresholds — always add your LEVEL to a `set`** (#320, character-file.ts): base thresholds are now **0/0**; ALL value comes from per-level bonuses computed from **L=1** (`levelThresholdSources(level, armored)`). `armored` = an enabled card SETS a threshold (armor or Bare Bones). Armored → per level +1 major / +1 severe (so set + level; a L1 armor 7/15 reads 8/16). Unarmored → +1 major / **+2 severe** per level (Major = level, Severe = 2×level; still 1/2 at L1). Shared `allEffectSources(file)` builds level-bonus + enabled-card sources for both `toSheetCharacter` and `sheetBreakdown`. No double-stack (applyLevelUp never touches thresholds). Pure engine unchanged.
- **Modifiers panel edits COMPLEX formulas** (#325, effects-editor.tsx + card-modifiers-sheet + card-editor): previously only flat ±N was editable; dynamic/byTier effects showed but editing did nothing (engine overrode). Now `toEditableEffects()` converts legacy dynamics (proficiency / halfAgility / strengthPlus3) → editable **formula**; `EffectFormula` gained `plus` (flat +constant, e.g. Strength **+3**) resolved after ×/÷ in modifiers.ts. EffectsField has 3 modes — flat / formula (variable ×/÷/+) / **by-tier** (T1–T4) — with a live `= N` preview. The formula VARIABLE is chosen from a **picker panel** (`FormulaVarPicker`), not a cycle — rendered at both the Modifiers-sheet and card-editor roots.
