The audio SFX system landed in **v0.2.11** (#255/PR #256). Engine = `src/lib/sfx.ts` on **react-native-audio-api** (Software Mansion Web Audio graph) — chosen over expo-audio because expo-audio's `setPlaybackRate` is buggy (brief pause/restart) and has no real fades. See [[runekeep_apk_build]] for the native-build gotcha (FFmpeg/foreground-service stripped via the plugin).

**Engine API** (`src/lib/sfx.ts`): `playSfx(id, opts?)` (one-shot, default subtle pitch variation via `detune` cents), `playRiser(id, {cents,volume})` → handle with `.stop(fadeMs)` (plays once, gain-ramps to silence — never an abrupt cut), `playLoseHp()` (rolls 1/10 → random meme from `OnLoseHP-1in10chance/`, else `OnLoseHP-Default`), `preloadSfx()` (called in menu mount), `setSfxVolume`/`setSfxMuted` (no settings UI yet — owner said stop making new UI). The require() import + `new AudioContext()` are **guarded in try/catch** → Expo Go runs SILENT, full audio only in the prebuilt APK. Per-id base volume + cents-spread live in `VOL`/`CENTS` maps; defaults 0.9 vol / 60 cents. Conventions: **every sound gets pitch variation EXCEPT** the meme folder (no variation) and consistency sounds (appStartup/sheetEnter/levelUpComplete/restComplete = 0 cents).

**Riser timing (the tricky part):** risers play on the **hold-to-charge path only** (heart-track + charge-track `begin`→start, `trigger`→`stopRiser(crossMs)` + delayed impact at the visual cross, `cancel`→fade). Double-tap & keypad damage = impact only. Multi-HP-loss (keypad) = **staggered per-heart** ~110ms apart, each rolls its own 1/10 meme. Goldify gain = `gainGoldenHp`; losing a golden heart = regular `loseHp`. Damage-panel OK hold uses `riserHp` at **-600 cents** (much lower), cut at completion → `panelClose` → the staggered losses.

**Owner's sound mapping (reuse for future sounds):** float menu select → panel open (panel mount fires it); card multi-select tap → cardSelect/cardDeselect (lower vol); delete cards → `tokenRemove`; beastform → `activateBeastform`/`disableBeastform`; ALL colour cycles (token + card random-colour) → `tokenCopyColor`; token drawer open/close → panel open/close; roster long-press → `floatMenuOpen`, delete character → `loseHpDefault` (NO meme); general button tap on every shared `RuneButton`/menu action (suppress with the new `muteSfx` prop where a climax sound already fires — confirm-level, random-colour); panels (FullScreenPanel/OverlayShell) → panelOpen on mount + panelClose on ✕/scrim; gear grind → one random `gearScroll1`/`2` per grind gesture; carousel center → `carouselScroll` tick.

**Normalization:** `scripts/normalize_sfx.py` (ffmpeg two-pass EBU R128 → **-16 LUFS / -1.5 dBTP** + leading-silence trim) over `assets/sounds/UI/**` (75 files). Short one-shots report `-inf` integrated → script falls back to single-pass. Re-runnable. Owner adds new raw sounds to `assets/sounds/UI/` (descriptive `OnXxx.wav/.mp3` names) then this normalizes them; add the id to `FILES` in sfx.ts + a trigger hook.

**Tuning file (#258, v0.2.12 work, PR #259):** `src/lib/sfx-config.ts` is the OWNER'S knob board — `SFX_VOLUME` (per-sound, 1=normalized level, >1 boosts), `SFX_PITCH_CENTS` (±cents, 0=no variation), `STAT_SOUND_DELAY_MS` (per-stat {gain,lose} ms after the hold before the impact sound; lower=earlier; SOUND-only, visual unchanged), `GEAR_FAST_FLIP_PX`, `PAGE_FLIP_VOLUME`. sfx.ts imports these. Owner fine-tunes by ear in Expo Go (but note: react-native-audio-api is native → NO sound in Expo Go; only the prebuilt APK has audio. Owner tests interaction/visuals in Expo Go, sound in the APK).

**Pass-2 additions (#258):** secondary carousels (StraightCarousel: creation/level-up/catalog) now have scroll pips + gear swoosh + quiet page-flip; the golden gear swoosh fires only on a FAST direction-REVERSAL while grinding (`GEAR_FAST_FLIP_PX`), so a plain tap-to-close/fullscreen-leave is silent; fullscreen-LEAVE reuses `transitionIconFilled` (the old leave file was ugly); creation Select button → cardSelect/Deselect, trait chips arm=buttonTap/clear=floatMenuClose, placing=cardSelect, trait tap=numpadPress; gallery filters (RuneChip) + drawer → buttonTap; origin badges (OriginCardPreview) → fullscreen enter/leave.

**Loading guard (#258):** `beginLoading()`/`endLoading()` in sfx.ts + a deferred-enter mechanism — NEVER play an "enter" chime (sheetEnter/panelOpen/enterCardViewer) while a LoadingScreen/CreateLoader is mounted; the latest is deferred and fires when the loader clears. Both loaders call begin/end on mount/unmount.

**Panel click-through — THE REAL ROOT CAUSE (#258r3, after 3 failed attempts):** a **fully-transparent** catcher (Pressable/View with NO backgroundColor) does NOT block — **gesture-handler hit-tests THROUGH it** to the hearts/charge-tracks (which use GestureDetector) underneath, so HP/stress change behind the panel. RN responder / `pointerEvents` / box-none / removing box-none all FAILED. The fix that works: give the catcher an **occluding backgroundColor (even `rgba(...,0.01)`) + `collapsable={false}`** so GH's hit-test treats it as solid and stops there. That's WHY FullScreenPanel (opaque bg) and the level-up backdrop (opaque) block, and why transparent catchers leaked. Applied the bg+collapsable fix to damage-panel, number-keypad, OverlayShell scrim, OriginCardPreview; SheetDim (zIndex 9500, pointerEvents none) still gives the visible dim. **Rule: any overlay catcher over the sheet needs a backgroundColor + collapsable={false}, NOT just pointerEvents.** Panels render zIndex 10000+; floatKind level/cards/custom also unload the carousel (but NOT the hearts — those need the occluding catcher).

**Loading-screen sound — THE REAL CAUSE (#258r3):** there are TWO loaders. `sheet.tsx` shows `LoadingScreen` "Unrolling the sheet" (file load); then `RedesignedSheet` shows **`RuneLoader` "Summoning the sheet"** (cards forge, `loaderUp`/`sheetReady`). `sheetEnter` fires on file-load → played while RuneLoader still up. Fix: EVERY loader must call `beginLoading()`/`endLoading()` (LoadingScreen, CreateLoader, AND RuneLoader). The deferred enter-chime then waits for the LAST loader to clear. When adding a new loader, wire the guard.

**On Select Characters** = the main-menu "Characters" button only (entering the roster). The roster row tap is SILENT (it opens the sheet → sheetEnter is the feedback; don't double up).
