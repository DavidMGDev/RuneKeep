# Starting again on a clean machine

Everything RuneKeep needs to be developed is in this repository, with one deliberate exception that is
named at the bottom. Work through this in order.

## 1. The toolchain

| What | Version | Notes |
| --- | --- | --- |
| Node | 20 LTS or newer | `npm` ships with it |
| Git | any recent | |
| Python | 3.11+ | only for `scripts/*.py` (card art colours, catalog generation, LOD thumbs) |
| Pillow | `pip install pillow` | the Python scripts that read images |
| 7-Zip | any | the APK builder extracts the Android SDK with it, and falls back to `Expand-Archive` |
| Java JDK | 17 | Android Gradle |
| Chrome or Edge | any | `scripts/web-probe.mjs` drives the real browser |

The Android SDK does **not** need installing by hand. `apk-build/build-apk.ps1` downloads every
component it needs by direct download, because `sdkmanager`'s own downloader stalls on this machine.

Nothing here is pinned to a machine: no absolute paths, no per-user config. The one global thing is
whichever GitHub account `gh auth status` reports, which the release step uses.

## 2. The project

```
git clone https://github.com/DavidMGDev/RuneKeep.git
cd RuneKeep
npm install
npx expo start            # phone, through Expo Go
npx expo start --web      # browser
```

**Expo is pinned to SDK 54** so the owner's Expo Go (54.0.8) runs it. Read the versioned docs at
<https://docs.expo.dev/versions/v54.0.0/> before writing native or config code; do not assume newer
API shapes. Use `npx expo install`, never plain `npm install`, for anything Expo tracks.

## 3. The checks

```
npx tsc --noEmit
npx jest
npx eslint src --ext .ts,.tsx
```

All three are expected to be clean; `eslint` has a handful of long-standing warnings and zero errors.

## 4. Building and releasing

```
npm run build:apk         # arm64 release APK, then a GitHub release
npm run build:apk -- -NoRelease    # build only
npx expo export --platform web --clear    # then upload dist/ to Cloudflare Pages by hand
```

The version comes from `app.json` › `expo.version` and nowhere else, so bump that and
`public/sw.js`'s `VERSION` together. `apk-build/release-notes.md` is the body of the GitHub release.
See `docs/web-deploy.md` for the Cloudflare half.

## 5. Claude's memory

`.claude/memory/` in this repository is a copy of everything Claude has learned about this project:
the release-by-release gotchas, the diagnoses that took a day to find, and the owner's standing rules.
It is the single most valuable non-code thing here.

To restore it on the new machine, copy the folder to where Claude Code looks for it:

```
# Windows
xcopy /E /I .claude\memory "%USERPROFILE%\.claude\projects\D--Tools-Homebrew-Daggerheart-RuneKeep\memory"

# macOS / Linux
cp -R .claude/memory "$HOME/.claude/projects/D--Tools-Homebrew-Daggerheart-RuneKeep/memory"
```

The folder name is derived from the project's absolute path, so if you clone somewhere other than
`D:\Tools\Homebrew\Daggerheart\RuneKeep` the slug changes. Start Claude Code in the project once, let
it create its own folder under `~/.claude/projects/`, then copy `memory/` into that.

`MEMORY.md` inside it is the index that gets loaded every session; the rest are loaded on demand.
Keep it in step: the copy in the repository is refreshed by hand, so re-copy it before wiping a
machine.

## 6. What is NOT in this repository, and why

`assets/temp/` is gitignored and stays that way. It holds licensed third-party material: the
Daggerheart Core Rulebook, the class-page extracts, The Void expansion's PDFs, and the full-resolution
card scans those were cut from. **This repository is public.** Publishing someone else's rulebook to a
public repository is a licensing problem rather than a size problem, which is why the ignore rule has
carried the note "licensed; transcribe to data, NEVER push" since it was written.

The app does not need any of it to build or run. Every card's text and numbers have already been
transcribed into `src/data/`, and the art the app actually ships is in `assets/art/` and
`assets/extracted_cards/`, both of which are committed.

Carry that folder across by hand, on a drive or through private storage. If you want it version
controlled, put it in a **private** repository and clone it into `assets/temp/`.

`node_modules/`, `android/`, `dist/` and `.expo/` are also absent and are all regenerated by the
commands above.
