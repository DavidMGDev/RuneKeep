# v0.12.5 — the REAL causes: stale forged-snapshot cache & the drop-flash commit race

Owner round-3 feedback: issues 1 (Void banners) and 3 (drop-flash) from v0.12.4 persisted on device.
Both v0.12.3/v0.12.4 attempts treated the wrong layer. This release fixes the actual root causes.

## 1. Void class banners (issue 1) — the fix was never on screen

Class cards are not rendered live: `useForgedSnapshots` captures each forged card ONCE into
`documents/forged/<key>-v<FORGE_RENDER_V>.png` and serves that bitmap forever. `FORGE_RENDER_V`
has been **15 since PR #235** — long before The Void. The six Void class cards were captured at
v0.12.2 with the then-broken banner (the faint sliver) and every banner fix since (v0.12.3 SVG
image, v0.12.4 expo-image) changed only the LIVE component that the cache was hiding. The webp
pennant assets themselves are verified good (proper red/gold pennants, transparent background).

Fix, two parts:
- **Bump `FORGE_RENDER_V` 15 → 16** — invalidates every cached forged card; all regenerate once.
- **Flag Void class/feature snapshot jobs `raster: true`** (creation `snapshotJobs`, sheet
  `classJob`/`featJobs`/`mcClassJob`/`mcFeatJobs`/`acqClassJobs`). The expo-image webp banner
  decodes asynchronously after layout — exactly the known player-photo capture hazard (#110/#121);
  without the settle, a fresh capture would forge a blank art zone and re-cache a broken card.

## 2. The one-frame drop-flash (issue 3) — stop racing the commit, bridge it

v0.12.4 held teardown two `requestAnimationFrame`s after the deck-change effect; the flash
persisted because JS rAF ordering does not bound when Reanimated ships the re-created worklet
closures (the new per-slot `index` captures) to the UI thread — shared-value writes travel a
faster path than closure rebuilds, so teardown could still land on a frame that rendered stale
indices with no drag state: one frame of the OLD arrangement.

Fix — make slot positions independent of `index`-prop timing entirely:
- New `pendingOrderSV: SharedValue<Record<string, number> | null>` — an **id → new-index bridge**.
- `finishDrop` writes the full new order into it **before** calling `onReorderCards`.
- Every slot's transform worklet resolves `idx = pendingOrder[item.id] ?? index` and positions off
  `idx`. A stale closure (old `index`) and a fresh one (new `index`) now compute the SAME position
  during the commit window, so `finalizeCommittedDrop` can reset drag state and deselect
  immediately — no rAF holds, no race, no flash by construction.
- The bridge is released 600 ms later (values then equal the live props — an invisible no-op) and
  defensively on the next edit-mode touch.

## Testing

`reorderBlock` and the commit data flow are already unit-tested; the bridge is UI-thread worklet
geometry (device-verified motion). Banner regeneration is device-verified render. Full suite:
312 tests / 26 suites, tsc clean, 0 lint errors.
