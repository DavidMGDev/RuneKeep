# v0.42.4 — One palette, real class pages, and a toolbar that fits

## Problem Statement

v0.42.3 shipped the authoring surface. Playing with it surfaced eleven problems, three of which are
the app doing something other than what it says.

- **Starting items forget what they are.** A class's item list prints "A card that is no longer here"
  for most of what was picked. The picker offers the whole card browser, including domain cards, and
  the list can only name an item it finds among the expansion's own gear and the base game's loot.
  Three of four rows are wrong in the owner's screenshot.
- **Campaign settings still look like character creation.** They open on Name and Portrait, which a
  campaign does not have. The button says "SELECT SUMMONER" when pressing it BANS the Summoner. There
  is a Random button, which in this mode picks a card at random to forbid. The expansion picker asks
  which packs to draw from, the draft is saved, and the leave-without-saving prompt fires: three
  ceremonies belonging to a character that is not being made. And nothing handles the case the whole
  feature exists for: the player's install not having the content the DM's rules name.
- **The section toolbar is a mess.** Bold is a WORD, wrapped onto two lines inside a square button.
  Alignment takes four buttons on a second row. The controls, the title field and the body field all
  sit on the same ground, so nothing tells you which control belongs to which.
- **The DM screens are grey.** The owner has decided against it: one app, one palette. And reaching a
  campaign takes two presses, through a mode toggle, when campaigns are the destination.
- **The class card asks the wrong question in the wrong place.** "What is this card, a new class or
  another page?" decides everything below it, and it is asked *inside* the editor, a third of the way
  down, after the author has already named the card and written sections. Starting Hit Points can be
  set to 0, which is not a character.
- **"Its voice" means nothing.** The section that asks for the class summary is titled with a phrase
  no author would search for, and nothing says the summary is the only text this card prints or how
  to add more.
- **Removing a section or a function is one tap with no confirmation**, so a mis-tap on the X takes
  authored text with it.
- **Class pages are numbered wrong.** A class card on the sheet starts at "2/4" because the cover page
  is counted but not shown.
- **Expand does the wrong thing entirely.** The owner: "the ONLY GOAL IS TO HAVE THE MULTI-PAGE CARDS
  RENDER EACH OF THEIR CONTENTS AS INDIVIDUAL CARDS." What it does instead is write new custom cards
  onto the character file, in the custom-card format, with a different plaque and a different look,
  and folds in things that were never on the class card.
- **A class card acquired from Add Gear cannot be expanded at all**, and carries the same broken
  numbering.
- **Tapping a trait does nothing unless the dice tray is already open.**

## Solution

**Starting items resolve against everything.** One resolver that knows the catalog, the loot tables
and every card in the expansion, so a picked card is named by its real title. The picker itself is
narrowed to what can actually be a starting item, so a domain card cannot be picked in the first
place.

**Campaign settings stop pretending to be creation.** The Details step becomes an explanation of what
this screen does. The primary button reads "Remove X" / "Restore X". Random becomes "Toggle all",
which turns the whole step on or off. The expansion picker, the draft save and the leave prompt do
not run. And a rule naming content the reader does not have is ignored rather than fatal.

**The toolbar becomes one band, one row.** A full-width strip behind the controls, running to the
section's own border, so the eye separates tools from the title field from the body field at a
glance. Bold is a bold **B**. Alignment is one button that cycles and shows the alignment it is on.
The reorder arrows shrink.

**One palette.** `DmRune` becomes the ordinary palette, so every DM screen adopts the app's colours in
one change and every `dm` prop stays harmless. The menu's mode toggle becomes a Campaigns button that
goes straight there, and the campaigns screen introduces itself the first time.

**The class card asks first, in a dialog.** Choosing "a new class" or "a page of a class" happens
before the editor opens, and cannot be changed afterwards: the answer shapes the card. Starting Hit
Points has a floor of 1.

**Plain copy.** "Its voice" becomes "What the card says", it explains that this is the only text the
card prints, and it points at the two ways to add more: another page for prose, a Feature card for
anything with a control on it.

**Removing asks.** A section or element with content in it confirms first. An empty one goes quietly.

**Class pages are the class's own pages.** Expanding stops writing custom cards. The class card's
pages become individual cards, derived, in exactly the format character creation draws them: the same
`ForgedTextCard`, the same class colour, the same banner, the same plaque. The cover page is skipped
everywhere on the sheet and the rest are numbered from 1. An acquired class card expands the same way.

**A trait tap opens the tray and rolls.**

## Implementation Decisions

### Starting items

- One resolver covers the catalog (`cardById`), the loot tables (`lootById`) and every card in the
  expansion, whatever its type. The current one only looked at the expansion's gear plus loot, which
  is why anything else read as missing.
- The picker is narrowed at the source: the browser opens on the item categories, and a card that
  cannot be a starting item is not offered. Both halves are needed, because the list must still name
  correctly the items an older pack already holds.

### Campaign settings

- The creator's campaign mode gains a mode-specific first step in place of Details: a plain
  explanation of what tapping a card does.
- The primary action's label is derived from the state of the centred card: "Remove X" while it is
  available, "Restore X" while it is not. It replaces the label logic only in this mode.
- Random becomes "Toggle all", operating on every option in the current step: if any is on, all go
  off; if none is on, all come back. `lib/campaign-settings` already has `setKeys`, which is exactly
  this.
- The expansion picker does not open, the draft is not written, and the leave guard does not run. All
  three are gated on the mode, not removed.
- **Unknown content is inert.** Restrictions are stored by option key, and a key naming content this
  install does not have simply matches nothing: `isOptionOn` already answers "allowed" for anything it
  has not been told about, and a disabled key for a card that is not there filters nothing out. The
  requirement is therefore that unknown keys are PRESERVED on save rather than pruned to what is
  currently installed, so installing the pack later brings the rule back. A test covers both
  directions.

### The section toolbar

- One row: the three format buttons, the alignment cycler, then the reorder and remove controls at
  reduced size.
- The band is a full-bleed strip: negative horizontal margins equal to the section's padding, so its
  edges meet the gold border rather than stopping short of it.
- Bold renders as a bold "B" glyph, italic and bullet keep their drawn icons, and alignment draws the
  alignment it is currently on and advances on press.

### One palette

- `DmRune` is redefined to the ordinary palette rather than deleted. Every `dm` prop, every
  `DmRune.x` reference and every `dm`-aware component keeps compiling and simply stops being grey.
  This is the whole of the visual change, in one file, and it cannot miss a screen.
- The menu's mode toggle becomes a Campaigns button that routes to the campaigns list. DM mode as a
  stored flag stays, because the menu still needs to know which pair of destinations to show; what
  goes is the toggle being the only way in.
- The campaigns screen shows a one-time introduction, persisted like the other onboarding flags.

### The class card

- The new-class / page choice moves to a dialog raised by the type chooser, before the editor opens,
  and the field is not editable inside the editor. Changing it means cancelling and starting again,
  which the dialog says.
- Starting Hit Points is floored at 1.

### Removing a block

- A section with a name or body, or any functional element, confirms before removal. An empty section
  removes without asking. The confirmation names what is being removed.

### Class pages, derived

- **`classExpanded` stops writing cards.** It becomes purely a rendering decision: when set, the
  class's feature pages are emitted as individual `CardItem`s built from the SAME jobs the paged card
  uses, so they are byte-identical to the creation cards. `lib/class-cards`'s card-writing half is
  removed; `isClassCard` stays so the migration can recognise what the old path wrote.
- **Migration is a tolerant read**: a file with `classExpanded` has the `cls-*` custom cards it was
  given filtered out, because the real pages are derived now. Nothing is rewritten on disk until the
  file is next saved for another reason.
- **The cover page is skipped on the sheet, everywhere**, and pages are numbered `i+1` of the page
  count without the cover. That is already true of the primary class card and becomes true of the
  acquired ones, which is the "2/4" defect.
- **An acquired class card is expandable**, tracked per acquired id on the character file. Expanded,
  it emits one card per feature page, same format, same numbering.

### Trait rolls

- The trait banners are always live. A tap opens the tray if it is shut and performs the roll once it
  is, which is a single deferred call rather than a second code path: the same handle method the open
  tray uses.

## Testing Decisions

A good test here asserts what a user could observe from a pure function's output. Prior art is
`src/lib/*.test.ts`, and the closest models are `campaign-settings`, `card-blocks` and `class-cards`.

- **starting-item resolution** — a catalog card, a loot item, an expansion card and a genuinely
  missing id each resolve to the right name.
- **`lib/campaign-settings`** — every existing test must still pass unchanged. New: a disabled key for
  content that is not installed filters nothing and survives a save/read round trip; `setKeys` used as
  toggle-all turns a mixed group all-off and an all-off group all-on.
- **`lib/class-cards`** — the page list a class expands into: the cover is absent, the count is the
  feature-page count, and the marks run 1..n. Plus the migration: a file carrying old `cls-*` custom
  cards comes back without them, and a file that never expanded is untouched.
- **`lib/markdown-marks`** — unchanged; the toolbar's rework is presentation only, and these tests are
  the guard that it stayed that way.
- **section removal** — the pure predicate for "does this need confirming".

Verified by the owner on device, per the standing rule: every layout change, the toolbar band, the
palette sweep, the campaign flow, and the trait roll.

## Out of Scope

- Changing what a class's feature pages SAY, or how `featurePages` packs them.
- Any change to the `.rune` format. Campaign rules already store unknown keys; nothing new is added.
- Removing DM mode as a concept. The menu still has two faces; only the way in changes.
- The character sheet's own palette, which is unchanged and owner-approved.
- Reworking Add Gear beyond making class cards expandable from it.

## Further Notes

- Items 8 and 10 are the same defect seen from two directions: a class card on the sheet counts a
  cover page it does not show. Fixing the rule once fixes both.
- Item 9 is a correction, not a feature: the previous implementation wrote data where it should have
  derived a view. The migration exists only because that data reached real characters.
- No user-visible string may contain an em dash.
