# v0.10.6 — creation polish + stress-pip seam fix

Four owner-reported items. Small, UI-only; no data-model or save-format change.

## 1. Select/Random buttons overlap the card carousel (class + weapons)
The bottom control cluster (`create-screen.tsx`, the `isCarouselDeck` overlay) sat too high and the
per-deck hint tooltips pushed it further into the cards.
- Removed the `deck === 'class'` "Tap the card to flip through its features" tooltip and the
  `deck === 'weapons'` "One-handed primary…" tooltip — dropping each cluster by ~one text line.
- Weapons also gets its filter Segmented row up top, which pushes its carousel down into the button
  band, so its cluster anchors lower: `bottom: deck === 'weapons' ? 40 : 56`.

## 2. Random button recenters the carousel on its pick
`StraightCarousel` gained an imperative `scrollTo(index)` (`StraightCarouselHandle`) that springs
`pos` to the index (closing a focused card first). `randomize()` now records the picked card id
(`focusId`), looks up its index in the current `items`, and calls `carouselRef.current.scrollTo(idx)`.
The carousel's derived-value center tracker keeps the parent's `centerIdx` in sync, so the SELECT
button still targets the recentered card.

## 3. Random compatible with Mixed Ancestry
When mixed mode is active, Random fills the two slots in order and then alternates re-rolling them:
press → 1/2, press → 2/2, press → re-roll first, press → re-roll second, … The slot decision is the
pure `nextMixSlot(first, second, alt)` in `create-types.ts`:
- empty `first` → fill first; else empty `second` → fill second (so a **deselect** always refills the
  freed slot, preserving the existing crossout-by-order system);
- both full → re-roll `alt`, flip `alt`.
The component holds `alt` in a ref (`mixRollNext`). Re-rolls exclude the other slot's card and the
slot's own current card so the pick visibly changes. Single-ancestry Random is unchanged.
Covered by `create-types.test.ts` (the exact press sequence + deselect refill).

## 4. Stress pips show white corner seams
The filled (`active`) and locked stress pips used the plain-View border-trick chamfer
(`ViewChamferFill`, #328), whose corner triangles abut the body on shared edges → anti-aliasing
hairlines. The outlined "empty" pips already use a seamless stroked SVG polygon. Fix: give the
filled/locked pips a **same-colour stroke** (`StressPip` in `redesigned-sheet.tsx`) so `ChamferFrame`
takes the same single-shape SVG path. No worst-case canvas added — a rested character already renders
every pip as an outlined SVG.
