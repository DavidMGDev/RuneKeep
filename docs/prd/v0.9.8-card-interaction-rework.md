# PRD — v0.9.8 Card Interaction Rework

Status: ready-for-agent · Target release: v0.9.8 (Android) · Author: agent (from owner stories, 2026-06-17)

## Problem Statement

As a player managing my character's cards, I only have one way to rearrange and manage them — the
Cards panel buried inside the Float menu. When I'm actually looking at my deck in the carousel, I
can't reorganize it without leaving the deck. The top of my sheet also spends three whole buttons
(Ancestry, Community, Subclass) on read-only origin previews I rarely open, which is prime real
estate. I have no way to mark cards as favorites for quick access. And two recent details feel
broken or missing: holding the gold "+" button adds ~3 gold and stops (or runs away if I tap fast),
and tapping my portrait gives no feedback so it feels like I can't change it.

## Solution

Add a second, in-place way to manage cards — **Golden Gear Edit** — that the player enters from the
deck they're already looking at, by holding the golden gear perfectly still. The curved deck
straightens into a flat row of small cards; tapping a card raises it (selects it); raised cards
expose the same management controls as the Cards panel (duplicate / move / delete / favorite / open
full panel) in a top-center toast-style bar, plus drag-and-swipe-up reordering with block insertion.

Reclaim the three origin buttons: replace them with an **Add card / Add gear** control on the left
and a **Favorites** star button on the right, filling the same footprint. Introduce **Favorites** —
a special built-in category of card duplicates with quick access from anywhere.

Fix the gold hold-to-bulk acceleration, and add a top-to-bottom **portrait shine** on tap (2× faster
on hold).

## User Stories

### Golden Gear Edit — entering / leaving
1. As a player viewing my deck, I want to enter an edit mode by pressing and holding the golden gear and holding still, so that I can rearrange cards without leaving the carousel.
2. As a player, I want a small movement tolerance (≈4px) on that hold, so that slowly scrolling the deck with the gear never accidentally triggers edit mode.
3. As a player who pauses mid-scroll, I want the dwell timer to re-arm only when my finger is actually still, so that a moving finger never enters edit mode.
4. As a player, I want the hold-to-enter time to be short and forgiving, so that entering edit mode feels easy, not finicky.
5. As a player entering edit mode, I want the curved deck to smoothly straighten — every card rotating to 0° and lining up in a flat horizontal row with even spacing — so that I can read the layout clearly.
6. As a player, I want the cards to stay at the small "gear-held" size after I let go of the gear, so that I keep an overview of many cards while editing.
7. As a player in edit mode, I want only the lowest-resolution card art (thumbnails) to load, so that dragging and reordering stays smooth.
8. As a player, I want to leave edit mode by an obvious affordance (e.g. a Done control / back gesture), so that the deck returns to its normal curved, full-size, readable state.

### Golden Gear Edit — selecting
9. As a player in edit mode, I want to tap a card to raise it ≈30% above the others, so that I can see it's selected without any extra highlight or background.
10. As a player, I want to tap multiple cards to raise several at once, so that I can act on a group.
11. As a player, I want to tap a raised card again to lower it (deselect), so that I can correct mistakes.
12. As a player, I want to keep scrolling left/right through the flat row while cards are raised, so that I can reach and select cards that are off-screen.
13. As a player, I want the selection controls to fade in (not pop) when at least one card is raised, and fade out when none are, so that the transition feels polished.

### Golden Gear Edit — the controls bar
14. As a player with cards raised, I want a controls bar near the top-center of the screen (toast-style, not on the very top edge), so that the controls are reachable and don't cover the deck.
15. As a player, I want a **Duplicate** control, so that I can copy the selected cards.
16. As a player, I want a **Move** control, so that I can move the selected cards to another category.
17. As a player, I want a **Delete** control, so that I can remove the selected cards.
18. As a player, I want a **Favorite** control, so that I can add the selected cards to Favorites.
19. As a player, I want an **Open Cards panel** control, so that I can jump to the full Cards management panel from here.
20. As a player, I want every control here to enforce the exact same safeguards as the Cards panel (locked categories, never-delete Gold/Beastform/Companion, keep-at-least-one-card, hold-to-confirm deletion, never-empty category, ≤5 active domain cards), so that editing in the carousel can never corrupt my sheet.

### Golden Gear Edit — reordering
21. As a player, I want to press-and-hold a card and drag it, with the other cards making room in real time, so that I can place it exactly where I want.
22. As a player, I want to swipe up on a card to immediately grab it for dragging, so that I have a fast alternative to press-and-hold.
23. As a player, I want the upward swipe to need clear intent (tolerant of horizontal scrolling), so that scrolling never accidentally grabs a card — mirroring how the real carousel distinguishes scroll from action.
24. As a player dragging a group of selected cards, I want them to gather into a temporary in-line "mini-carousel" block with the same spacing as the deck, so that I can see exactly where the block will land.
25. As a player, I want the underlying deck to rearrange as if the grabbed cards were removed, so that I can read the resulting layout while I position them.
26. As a player moving the block near the deck, I want the deck to open a gap sized for the whole block (computed as one block, not per-card), so that reinsertion is smooth and cheap.
27. As a player who drags the block away from the deck, I want the deck to settle back to normal, so that I can choose a new insertion point.
28. As a player dragging near the left or right ≈15% edge of the screen, I want the flat row to auto-scroll (at a speed relative to the category size), so that I can reach a distant insertion point without lifting my finger.
29. As a player, I want to drop a dragged group onto a controls-bar button (e.g. Move/Delete/Favorite) and have it treated as "these cards selected, then that button pressed," so that I can act on a group by dragging as a convenience.
30. As a player, I want all reordering to persist to my saved character, so that my arrangement survives app restarts.

### Golden Gear Edit — constraints
31. As a player in edit mode, I do NOT want to open cards full-screen or read their detail, so that the mode stays focused on editing.
32. As a player, I want edit mode to operate on the deck I was already viewing (the current category), so that I edit what I was looking at.

### Replacing the origin buttons
33. As a player, I want the Ancestry, Community, and Subclass buttons removed from the top of my sheet, so that the space is used for actions I take more often.
34. As a player, I want the freed space filled with new buttons that don't shift any surrounding UI, so that my sheet still looks balanced.
35. As a player, I want a left button to **Add card** for the current category (the same author flow as the Float menu's New Card, but without the "from catalog/gear" option), so that I can quickly create a card.
36. As a player, I want the same left control (or its other half) to **Add gear** — jumping straight into the catalog/gear browser for the current category, so that I can add equipment fast.
37. As a player, I want a right **Favorites** button (a star), so that I can open my favorites from anywhere on the sheet.
38. As a player, I want removing the origin buttons to not change the carousel or any cards in any way, so that only the dead origin-preview UI goes away.

### Favorites
39. As a player, I want a Favorites category that holds duplicates of my cards, so that I can keep my most-used cards together without removing them from their real category.
40. As a player, I want every card in Favorites to be a duplicate (never the only copy), so that managing favorites never risks my real cards.
41. As a player, I want Favorites to NOT appear in the Move panel, so that I can't accidentally move a card "into" favorites the wrong way — favoriting is its own action (the star).
42. As a player, I want the Favorites category to be un-deletable but disable-able, so that it's always available but doesn't clutter my loop when I don't use it.
43. As a player, I want Favorites to start disabled and become enabled once I have at least one favorite, so that it appears exactly when it's useful.
44. As a player who deletes a card inside Favorites, I want that to just un-favorite it (remove the duplicate) without touching or affecting the original, so that removing a favorite is safe.
45. As a player who deletes an original card, I want its favorite duplicate(s) removed too, so that Favorites never shows dead cards.
46. As a player, I want favorite duplicates to stay perfectly in sync with their source — same enabled/disabled state, same card edits, same placed tokens and dice — so that a favorite is a true mirror, not a stale copy.
47. As a player with Favorites enabled as a category, I want it to participate in the normal over-scroll loop like any other category, so that it behaves consistently.
48. As a player with Favorites disabled, I want to reach it only via the Favorites button, and when I'm in it, over-scrolling left OR right both return me to the category I came from, so that the button is a temporary detour rather than a loop member.
49. As a player, I want the over-scroll labels on both sides to read my origin category's name while in button-opened Favorites, so that I always know where I'll land.
50. As a player who scrolls back to my origin category, I want the loop to behave normally again, so that the detour cleanly ends.
51. As a player, I want the Favorites button to also be available inside Golden Gear Edit, so that I can favorite while editing.

### Gold card hold-to-bulk (fix)
52. As a player, I want to hold the gold "+" (or "−") and have it keep adding (or removing) gold smoothly, so that I don't tap dozens of times.
53. As a player, I want the rate to start reasonably and ramp up the longer I hold, so that bulk changes are fast but controlled (gold is precious — it shouldn't explode instantly).
54. As a player, I want it to stop the instant I lift my finger, so that gold never keeps changing after release.
55. As a player, I want fast tapping to never start a runaway, so that the only way to bulk-change is an intentional hold.
56. As a player, I want hold-to-bulk to work ONLY on the gold card, so that other steppers are unaffected.

### Portrait shine feedback (fix)
57. As a player who taps my portrait, I want a quick top-to-bottom shine sweep, so that I get a clear, attractive confirmation the tap registered.
58. As a player who holds my portrait (to replace it), I want the shine to sweep ~2× faster, so that the hold feels responsive rather than slow.
59. As a player with no portrait yet, I want the "tap to add" target to give the same shine feedback, so that it's obviously interactive.

## Implementation Decisions

### Modules

- **`favorites` module (pure, new).** Encapsulates the Favorites rules over the `CharacterFile`:
  `isFavorited(file, ref)`, `addFavorite(file, sourceCardId) → file`, `removeFavorite(file, favCopyId) → file`,
  `cascadeRemoveFavorites(file, deletedCardIds) → file`, and `favoritesEnabled(file)`. A favorite is a
  `cardCopy { id: 'fav-…', ref }` whose `cardCategory[favId] = 'favorites'`. This reuses the existing
  copy/override machinery — no new persistence shape beyond marking the copy as a favorite. Deep,
  testable, no React.
- **`gold-stepper` repeat (extracted helper).** A small press-repeat controller with a single
  per-press timer, ramp curve, and "stop on release / never overlap presses" guarantee. The accel
  curve (start delay, decay factor, floor) is a pure function that can be tested deterministically.
- **`carousel-edit` state (new, in carousel-context).** Shared values + JS state for: `editMode`
  (0→1 straighten progress), the raised/selected set, the active drag group, and the block-insertion
  index. Drives the existing `CardSlot` `useAnimatedStyle` via a single progress value (arc→flat lerp)
  rather than mounting a second carousel.
- **Carousel layout (modified).** `CardSlot`'s per-frame transform gains an `editMode` lerp:
  `tilt → 0`, curved `y → flat y`, fan `x → linear-spaced x`. The same `editMode` value damps full-res
  image opacity to force lowest LOD (the exact mechanism the gear grind already uses), and pins card
  scale to the small gear-held size.
- **Gear dwell detector (modified gesture).** Inside the existing single full-sheet `Gesture.Pan`,
  add a stillness dwell: on pad touch-down start a timed shared value; in `onUpdate`, if movement from
  the anchor exceeds the tolerance, cancel and re-anchor; on completion, enter edit mode. Rides
  alongside the existing slow-scroll branch so scrolling is unaffected.
- **Edit controls bar (new component).** Top-center toast-style bar; fades in on selection. Buttons
  delegate to the EXACT existing sheet handlers (`onDuplicateCards`, `onMoveCards`, `onDeleteCards`,
  reorder handlers) so all safeguards are inherited, plus a Favorite action (favorites module) and an
  "open Cards panel" action.
- **Top-of-sheet actions (modified).** Remove the three `OctaBadge`s + their dead origin-preview path
  (`onOpenOrigin`, `originPreview` state, the `OriginCardPreview` overlay + file, the already-dead
  `openOriginCard`/`originIndices` context path, and the now-unused origin art/Octagon frame). Replace
  with an **Add card / Add gear** control (left) and a **Favorites** star button (right) occupying the
  same x176→380 / y124→190 band, with the two `GoldRuleV` dividers re-placed or removed.
- **New-card entry without catalog (reuse).** Add card uses the existing `NewCardFlow` with the
  catalog option suppressed (mount without the `onAcquire` prop, which is the existing gate for the
  "from catalog" button). Add gear opens the existing `GearBrowser`/catalog path directly, routed to
  the current category via the existing `onAcquireCard`.
- **Portrait shine (modified).** Reuse the portrait's existing Reanimated + react-native-svg ClipPath
  pattern: a new shared value 0→1 sweeps a clipped highlight band top→bottom; a tap gesture (added to
  the existing gesture composition) plays it at base speed, the existing long-press plays it ~2× faster.

### Key decisions / clarifications

- **Favorites are duplicates, implemented on the existing `cardCopies` + `cardCategory` machinery.**
  No new top-level schema; a favorite is a copy routed to the special `favorites` category. This makes
  enabled-state and content edits already shared by `ref` (verified true today).
- **Token & dice sync across duplicates — DECISION: make them shared by `ref`.** Today, placed tokens
  and dice are stored PER-INSTANCE (keyed by deck-instance id), while enabled-state and edits are
  SHARED (keyed by `ref`). The owner's spec requires favorites (and duplicates generally) to be
  "perfectly in sync," including tokens and dice. Decision: tokens/dice will be keyed by `ref` so all
  instances of the same card (favorites included) share one token board, with a read-time fallback to
  any legacy per-instance entries for back-compat with existing saves. Trade-off recorded: independent
  per-copy token tracking is no longer possible. (If the owner wants per-instance tokens preserved for
  non-favorite duplicates, this can be scoped to favorites only — flagged for confirmation.)
- **`favorites` is a special built-in category** added to the category system but excluded from the
  Move panel and from `LOCKED_CATS`-style restrictions except: cannot be deleted; can be disabled;
  auto-enabled when the first favorite is created; deleting inside it = un-favorite (remove copy only).
- **Disabled-Favorites over-scroll is a transient detour.** When Favorites is disabled and opened via
  the button from origin category X, a transient `favoritesOrigin = X` makes both over-scroll
  directions cycle back to X and both indicator labels read X's name. Returning to X clears it and the
  loop resumes normally. When Favorites is enabled, it is a normal ring member (no special-casing).
- **Edit mode reuses the always-mounted carousel slots** (no second fan, no unmount/fade of the
  carousel) per the architecture perf rules; arc→flat is a single shared-value lerp on the existing
  `useAnimatedStyle`, and LOD is forced to thumbnails via the existing grind-style opacity damp.
- **Group drag uses pre-computed block geometry** (block width = N cards × spacing) so the deck opens
  one gap for the whole group rather than recomputing per card — cheaper and visually clear.
- **All destructive/structural edit-mode actions go through the existing sheet handlers** so deletion
  rules, never-empty guards, hold-to-confirm, and the ≤5 active-domain cap are inherited unchanged.
- **Gold hold-repeat rewrite**: one timer owned per press, cleared before any (re)schedule; latest
  amount read via ref; the button is NOT disabled mid-hold (the repeat self-stops at the ceiling/floor
  by detecting a no-op step); release always stops. Scoped to the gold card only.

## Testing Decisions

Good tests here assert external behavior, not implementation details — given a `CharacterFile` (or
inputs), assert the resulting file/return value, the way `character-file.test.ts` and
`carousel-categories.test.ts` already do for pure modules.

- **`favorites` module** — unit tests: favoriting creates a duplicate copy in `favorites`; a card can't
  be favorited twice; un-favorite removes only the copy and leaves the source untouched; deleting a
  source cascades to remove its favorite copies; `favoritesEnabled` flips with favorite count; favorites
  never appear in the Move category list. Prior art: `character-file.test.ts`, `carousel-categories.test.ts`.
- **Token/dice ref-sync** — unit test on the token read/write helpers: writing a token under one
  instance is visible to another instance of the same `ref`; legacy per-instance entries still read.
  Prior art: `character-file.test.ts` resource-persistence tests.
- **Block-insertion index math** — pure helper test: given a drop x-position and a flat-row layout,
  the computed insertion index and gap geometry are correct at boundaries (start, middle, end).
- **Gold accel curve** — pure test of the delay-ramp function: starts at the base delay, decays by the
  factor, never goes below the floor; a no-op step signals stop.

Animation/gesture feel (straighten, raise, shine, edge-scroll, dwell tolerance) is verified manually
on-device by the owner per project convention — not screenshot/automated-tested.

## Out of Scope

- Reading cards or opening them full-screen inside Golden Gear Edit (explicitly excluded).
- Reworking the existing Float-menu Cards panel (it stays as the primary management surface; edit mode
  is additive).
- Changing how non-duplicate cards behave anywhere outside the token/dice keying decision above.
- Any new persistence backend (still bundled/offline, no DB).
- iOS-specific work beyond keeping the app runnable in Expo Go.
