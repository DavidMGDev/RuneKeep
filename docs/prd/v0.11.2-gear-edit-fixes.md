# v0.11.2 — Golden Gear Edit: fixes + drag repair

PRD (via `/to-prd`). Fourth pass on Golden Gear Edit. This round is mostly **bug repair** of the
v0.11.1 rework (the enter transition and the drag-to-rearrange regressed) plus small polish. Published
as a `docs/prd` doc (the project's convention) rather than an external issue tracker (not configured).

## Problem Statement

The owner tried v0.11.1 on device. Edit mode is broken in ways that make it unusable or dizzying:
entering flashes/reverts/re-lays-out the cards several times before settling; rearranging cards never
commits (they freeze mid-air and the mode wedges); dragged cards vanish when moved a few slots; the
hold-to-open action wheel closes itself while still held; the device Back button half-exits the mode;
and several proportions are off (badge shape/background, card raise height, banner distance, wheel
icon size and transparency).

## Solution

Repair the enter transition to a single seamless straighten, make the drag reliably commit (and
deselect on a real move), stop dragged cards from fading, keep the wheel open until release, make Back
fully exit the mode, and dial in the proportions the owner called out. Add a synced vertical swipe
indicator on selected cards, floatier edit scrolling, and a 2× gear scroll in edit.

## User Stories

1. As a player entering edit mode, I want the curved gear-scroll fan to straighten into the edit row in ONE seamless motion, so that I'm not made dizzy by the cards resizing and jumping several times.
2. As a player entering edit mode, I don't want the hand to briefly revert to the expanded gold fan before desaturating, so that the transition reads as one deliberate change.
3. As a player holding a card to open the action wheel, I want the wheel to stay open whether or not I move my finger, so that it never closes on me mid-decision.
4. As a player using the action wheel, I want it to close with no action ONLY when I release outside any option, so that releasing on an option always fires it and releasing in the middle always cancels.
5. As a player rearranging cards, I want the cards I drag to animate up to my finger, so that grabbing feels alive, not a snap.
6. As a player rearranging cards, I want the carousel cards to animate as they make room, so that the reflow reads as motion, not a teleport.
7. As a player rearranging cards, I want the cards I'm dragging to stay visible no matter how far I move them, so that they never vanish mid-air.
8. As a player, I want the ghost/reflow animations ~20% slower, so that the placement reads clearly.
9. As a player releasing a rearrange, I want it to actually commit — the cards settle into their new order and stay there, so that rearranging is possible at all.
10. As a player, I never want edit mode to wedge (freeze until I tap, then revert), so that it's always responsive.
11. As a player who makes a real rearrange, I want the moved cards deselected afterward, so that I can tell it took.
12. As a player who drops cards back where they started, I want them to stay selected (no change = no commit), so that a non-move isn't treated as an action.
13. As a player, I want a vertical swipe indicator (upward half-arrows) on every selected card, fading in/out in sync with the selection breathe, so that it's obvious selected cards can be dragged up.
14. As a player scrolling the edit row, I want a floatier, momentum feel that only snaps as it slows, so that it doesn't feel heavy.
15. As a player, I want the bottom gear to scroll the edit row 2× faster than swiping the cards, without shrinking them, so that I can cross a big deck quickly in edit.
16. As a player, I want the device Back button to fully exit edit mode in one press, so that the mode is never half-on (no hanging banner, dim, or cards).
17. As a player, I want selected cards to lift only slightly (~5px), so that the row stays tidy.
18. As a player, I want the action wheel icons 25% larger and the wedge backgrounds more opaque, so that they're easy to read.
19. As a player, I want the "Edit Mode" banner higher up (away from the cards), so that it doesn't crowd the row.
20. As a player, I want the Add Card / Add Gear / Favorites badges to have transparent (not dark-gray) backgrounds, so that they match the sheet.
21. As a player, I want those badges square (not tall), so that they look balanced.
22. As a player, I want the Add Card glyph slightly taller (not square) with Add Gear matched, so that it reads as a card.
23. As a player, I want the origin/level/proficiency header text spaced so the domains sit near the name, level+proficiency sit near the domains, and there's breathing room before the badges.

## Implementation Decisions

**Enter transition (stories 1–2, the "dizzy" bug).** Root cause: entering runs several competing
animations — the gear-grind shrink relaxing, `expandProgress` re-springing, `editMode` straightening,
plus a possible collapse-then-recover. Decision: entering edit must be a SINGLE straighten. Drive the
edit row directly off the same geometry as the grind fan so that at `editMode = 0` the row IS the grind
fan and at `editMode = 1` it's the straight row — one interpolation, no size/expand re-animation, no
revert-to-gold frame. The gear white flash melts straight into the desaturation.

**Action wheel stays open (stories 3–4).** Root cause: the wheel is driven by the carousel master pan;
a competing per-card gesture (the long-press) cancels that pan while the finger is still down, whose
`onFinalize` then closes the wheel. Decision: once the wheel is open, its lifecycle must not depend on
the master pan being cancellable — either make the per-card gestures simultaneous with the master pan
(so nothing cancels it) or disable the per-card long-press in edit mode. The wheel closes on a genuine
finger-lift only: release on a wedge → fire; release in the dead-zone/off the ring → cancel.

**Drag commit repair (stories 5–12) — the CRITICAL fix.** The v0.11.1 staged bridge (keep `editGrabbed`
on until a deck-change effect fires) is too fragile — when the reorder is a data-layer no-op the effect
never fires and the mode wedges. Decisions:
- The drop MUST reliably reset the drag state and re-enable the mode, even if the reorder changes
  nothing (a safety path that never leaves `editGrabbed` stuck).
- Commit is: on release, animate the gap to the block width and the pile into it (~20% slower), then
  persist the reorder via the existing group-reorder handler.
- Dragged (piled) cards and reflowing cards must compute their VISIBILITY from their displayed position,
  not their original deck index — so a card dragged several slots away never falls out of the mount/opacity
  window (story 7).
- The pile eases to the finger and the reflow gap glides (stories 5–6); a real move deselects, a no-op
  does not (stories 11–12) — decided by comparing the committed order to the prior order (`reorderBlock`
  already returns the new order; equality with the old order = no-op).

**Swipe indicator (story 13).** A small three-chevron upward indicator overlaid on each selected card,
its opacity driven by the SAME shared breathe value as the selection glow, so all selected cards pulse
in sync and a newly-selected card fades into the shared pulse.

**Edit scroll feel (stories 14–15).** Lighter momentum on the edit-row fling (carry more velocity, snap
later). The bottom gear in edit scrolls the row at 2× the finger-swipe rate WITHOUT the grind shrink
(cards keep the edit size).

**Back button (story 16).** The sheet's back handler must treat edit mode as a first-class overlay:
if edit mode is on, Back exits it fully (dim + banner + row + selection all cleared) and consumes the
press, before any "leave character sheet" prompt.

**Proportions (stories 17–23).**
- Selected-card raise → ~5px (`EDIT_RAISE`).
- Wheel icons +25%, wedge fill opacity raised to ~0.85 (≈15% transparent).
- "Edit Mode" banner moves up 1.5× its own height.
- Badge frame fill → transparent (keep the active gold fill); badge box made square.
- Add Card glyph +2px height (Add Gear scaled to match).
- Header text vertical spacing: domains near the name, level+proficiency near the domains, negative
  space before the badge row. `/impeccable layout` used to sanity-check the arrangement; only vertical
  offsets change, never the text.

## Testing Decisions

Good tests here check external behavior of PURE logic, not animation. The drag's pure core is
`reorderBlock` (already unit-tested in `edit-drag.test.ts`) — extend it to assert the no-op case
(dropping a block back at its own position returns the identical order), which is exactly the signal the
commit uses to decide "changed → commit + deselect" vs "no-op → keep selection." No new tests for the
gesture/animation glue (owner-verified on device, per the project norm). Wheel option list stays covered
by `card-menu.test.ts`.

## Out of Scope

- A per-pixel desaturation shader (the grayscale-twin crossfade stays; Skia is a separate follow-up).
- Reworking which card categories are data-reorderable (if a category's deck order isn't driven by
  `cardOrder`, that's a separate data-layer concern; the safety path makes it non-fatal, not silently wrong).
- Any change to the card text content in the header (only vertical positions move).

## Further Notes

This is a repair-heavy release: items 3, 4, and 8 are regressions from v0.11.1's own rework, so the bar
is "reliable and calm," not "more features." Motion + look are owner-device-verified.
