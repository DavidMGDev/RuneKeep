# v0.15.0 — DM Mode: Parties, Sessions & Encounters

The first Dungeon Master surface. RuneKeep has been a player's companion; this release adds a parallel
DM identity — a desaturated palette, a Parties/Sessions/Encounters hierarchy, an at-a-glance party
overview, manual adversaries, a heartbeat-style stat control, and a per-encounter log — all sitting on
the existing character roster and reusing the sheet's visual language.

## Problem Statement

The person running the table has nothing. Every screen in RuneKeep speaks to one player controlling one
character. A DM juggling 3–6 heroes plus a bench of adversaries has to track hit points, stress, damage
thresholds and the flow of a fight on paper or in their head. They can't group the party's characters,
can't see everyone's vitals at a glance, can't prepare a fight in advance, and can't keep one shared
record of "where the party is right now" that survives from one encounter to the next.

## Solution

A DM Mode toggled from the main menu. Enabling it recolours the whole DM surface into the same
desaturated palette as Golden Gear Edit, and re-labels the two menu actions: **Cards → Sessions**,
**Characters → Parties**. From there the DM:

- Builds **Parties** — named, coloured collections of characters picked from the device roster (now
  organisable into folders). A party is enabled once populated; enabling it unlocks Sessions for it.
- Opens **Sessions** for a chosen party — each session is a list of **Encounters** with the active one
  pinned at the top.
- Sees a **Party Overview / Player list** — one compact horizontal panel per character showing image,
  name, subclass, HP, Evasion, Armor, thresholds, Stress and Hope as numbers-that-mean-the-icons; taps
  to expand into traits/level/proficiency.
- Runs an **Encounter** — the toggled-on party members auto-added as allies, adversaries added manually
  (name + optional HP / thresholds / stress / description), each combatant's stats nudged by a
  **heartbeat pulse** control (hold to repeat, tap the number to type it) or read directly.
- Keeps the party's living vitals in one **global state** that every synced encounter shares, and
  **archives** that state the moment an encounter is marked complete — so fights can be prepped ahead and
  still open in sync with the party's current condition.
- Records events in a per-encounter **log** (markdown, newest first), optionally auto-logging every stat
  change.

## User Stories

1. As a DM, I want a "DM Mode" button on the main menu below Cards, so that I can switch the app into a DM-facing surface.
2. As a DM, I want enabling DM Mode to recolour the DM interfaces into the desaturated Golden-Gear-Edit palette, so that I always know at a glance whether I'm looking at player or DM content.
3. As a DM, I want the menu's "Cards" and "Characters" buttons to become "Sessions" and "Parties" while DM Mode is on, so that the menu speaks to my role.
4. As a DM, I want the "DM Mode" button to read "Player Mode" while active and to revert everything — palette and labels included — when tapped, so that leaving DM Mode is one tap and total.
5. As a DM, I want DM Mode to persist across app restarts, so that I stay in the mode I chose.
6. As a user (either mode), I want to make folders in the characters list with a name and a colour, so that I can group related characters.
7. As a user, I want to rename a folder, so that I can correct or re-theme it.
8. As a user, I want folder (and party) colours assigned at random and re-rollable but not hand-picked, so that colouring stays consistent with how the rest of the app assigns identity colour.
9. As a user, I want an imported character that already exists on the device to overwrite the existing one instead of duplicating, so that re-importing an updated character updates it in place.
10. As a DM, I want to create any number of parties, so that I can run different tables.
11. As a DM, when no party exists and I open Parties, I want to be prompted to create my first party, so that the empty state guides me.
12. As a DM, I want a party to be a collection of characters chosen from the device roster, so that a party reflects real saved heroes.
13. As a DM, I want the party's character-selection UI to feel like the player character-selector but as a multi-select over existing characters with no maximum, tuned for 3–6, so that picking a party is familiar and fast.
14. As a DM, I want to import a character directly from the party selection UI, so that I can add a friend's hero to the party without leaving the flow.
15. As a DM, I do NOT want to *create* a new character from the party selection UI (only import/select), so that character authoring stays in its one place.
16. As a DM, I want each party member to have a present/absent toggle, so that I can drop a character who isn't at this session or encounter.
17. As a DM, I want to "Enable" a party once it has members, so that enabling it unlocks the Sessions button for that party.
18. As a DM, I want the Sessions button to stay locked until at least one party is enabled, so that I don't reach an empty Sessions surface.
19. As a DM, I want the Sessions screen to select its party from a dropdown of all created parties at the top, so that I can switch which party's sessions I'm viewing.
20. As a DM, I want to create any number of sessions under a party, so that each play session gets its own record.
21. As a DM, I want a session to show its encounters as a list with the Active Encounter pinned on top and the rest newest-to-oldest, so that the current fight is always front and centre.
22. As a DM, I want a "Players" button in the session's encounter list, so that I can open the party overview at any time.
23. As a DM, I want the player list to show one compact horizontal panel per character by default — small image, name, subclass, HP/MaxHP, Evasion, available Armor, thresholds (xx/XX), Stress/Max, Hope — as numbers standing in for the sheet's icons, so that I can read the whole party at a glance.
24. As a DM, I want to tap a character panel to expand it into traits, level and proficiency, so that I can see detail on demand.
25. As a DM, I want the player list optimised for 3–6 characters but scrollable beyond, so that big tables still work.
26. As a DM, I want a "New Encounter" button that opens an "Encounter #X" (X = existing count + 1), so that encounters are numbered automatically.
27. As a DM, I want every action inside an encounter saved to storage immediately, so that I never lose encounter state.
28. As a DM, I want an encounter to have an allies list and an adversaries list, so that I can see both sides.
29. As a DM, I want the encounter to auto-add the toggled-on party members as allies, so that I don't re-pick the party per fight.
30. As a DM, I want to add NPC allies manually, so that non-party allies can join a fight.
31. As a DM, I want to add adversaries manually, defaulting to "Adversary #X" and renameable, so that I can stub out a fight quickly.
32. As a DM, I want each adversary/NPC to optionally display HP/MaxHP, thresholds, Stress and a description, so that I only track what matters for that combatant.
33. As a DM, I want to prepare encounters in advance, so that a session's fights can be built before play.
34. As a DM, I want a party's vitals kept as a shared "global" state that synced encounters read, so that prepared encounters open in sync with the party's current condition.
35. As a DM, I want only the active encounter and the party overview to be able to change global party state, so that browsing a prepared or finished encounter can't corrupt the live state.
36. As a DM, I want completing an encounter to archive the party state at that moment onto the encounter, so that I can look back at how the fight left the party and keep using the current state going forward.
37. As a DM, I want an option to make an encounter fully local (global sync off), so that a one-shot or hypothetical fight doesn't change the party across other sessions.
38. As a DM, I want to change a combatant's HP/Armor/Stress/Hope by tapping the icon to toggle increase/decrease and holding it to pulse repeatedly, so that adjusting stats is fast and tactile.
39. As a DM, I want the pulse to behave like a heartbeat — reach an activation point, pause, and keep returning to it while I hold — applying one step per beat, so that I feel each step.
40. As a DM, I want the pulse to speed up the longer I hold and to give an audio cue per activation point, so that I can count steps without watching the number.
41. As a DM, I want to tap a combatant's stat number to type an exact value on the existing keypad, so that I can set a value directly instead of stepping to it; entering nothing makes no change.
42. As a DM, I want HP/Armor/Stress/Hope pulse controls for party members and HP/Stress for adversaries (no armor/hope), so that each combatant exposes only the stats it has.
43. As a DM, I want each encounter to have a log of markdown entries newest-first, so that I can record the order of events.
44. As a DM, I want to add free notes to the log, so that I can capture context in my own words.
45. As a DM, I want an option to auto-log stat changes as single entries — who (player/adversary + name), what changed, and the resulting value — so that the fight records itself.
46. As a DM, I want a hold-based stat change (press → release) recorded as one log entry, not one per beat, so that the log stays readable.
47. As a DM, I want the auto-log toggle and the global-sync toggle to live together in an encounter options panel, so that I control an encounter's recording and sync behaviour in one place.
48. As a DM, I want all these interfaces built in the established RuneKeep visual language (DesignStage, ChamferBox, Rune palette desaturated, sheet-style icons), so that DM Mode feels native to the app.

## Implementation Decisions

### Palette & mode
- **`DmRune` palette** added beside `Rune` in `constants/theme.ts`, reusing the Golden-Gear-Edit
  desaturated tones already in the sheet (`#C4C8D0` / `#9AA0AA` grays, muted panel fills). DM screens
  import `DmRune`. The menu, while DM Mode is on, restyles its own chrome with it.
- **DM Mode flag** is a persisted device-local singleton (`lib/dm-mode.ts`: `getDmMode`/`setDmMode` over
  the same file/localStorage shim the stores use) surfaced through a tiny `DmModeProvider` context so the
  menu (and any screen) reads it synchronously. Toggling is total and reversible — it changes nothing
  about stored data, only which palette/labels render.

### Data model — pure, testable modules
- **`lib/party.ts`** — `Party { schemaVersion, id, name, color, createdAt, memberIds[], present: Record<charId,bool>, enabled, global: PartyGlobalState }`. `PartyGlobalState = Record<charId, MemberVitals>`, `MemberVitals { hp, stress, hope, armor }` (current values; maxes are derived from the character file via the existing `toSheetCharacter`, never stored on the party). Reducers: `newParty`, `addMembers`, `removeMember`, `togglePresent`, `setEnabled`, `initMemberVitals(file)`, `applyVitalDelta`, `setVital` (all clamp to the derived max/0). `partyIsPopulated`.
- **`lib/session.ts`** — `Session { schemaVersion, id, partyId, name, createdAt, activeEncounterId? }` and `Encounter { schemaVersion, id, sessionId, index, name, createdAt, status:'prepared'|'active'|'completed', allies: Ally[], adversaries: Combatant[], log: LogEntry[], options:{ globalSync, autoLog }, localVitals?: Record<charId,MemberVitals>, archivedGlobal?: PartyGlobalState }`. `Ally = { kind:'member', charId } | { kind:'npc', combatant: Combatant }`. `Combatant { id, name, hp?, maxHp?, thresholds?, stress?, maxStress?, description?, show:{hp,thresholds,stress,description} }`. `LogEntry { id, at, kind:'note'|'stat', text }`. Reducers: `newEncounter(index)`, `nextIndex(encounters)`, `addAdversary` (auto-name `Adversary #X`), `addNpc`, `renameCombatant`, `applyCombatantDelta`/`setCombatantStat`, `appendLog`, `formatStatLog(side,name,stat,to)`, `setActive`, `completeEncounter(party)` → freezes `archivedGlobal` + status `completed`.
- **Global vs local resolution** — `memberVitals(encounter, party, charId)` returns `party.global[charId]`
  when `options.globalSync` and the encounter is the active one; otherwise the encounter's `localVitals`.
  Writes: only the **active** encounter (and the party overview) may write `party.global`; a synced write
  from the active encounter mutates the party, a non-synced encounter writes `localVitals`. `completeEncounter`
  snapshots `party.global` into `archivedGlobal`; the party's `global` is untouched and carries forward.
  Adversaries/NPCs are always local to their encounter.
- **`lib/folders.ts`** — `FolderIndex { folders: Folder[], assignments: Record<charId, folderId> }`,
  `Folder { id, name, color }`. Reducers: `addFolder`, `renameFolder`, `recolorFolder` (random from the
  identity palette, matching how the app already assigns colour), `assign`, `unassign`, `removeFolder`
  (its members fall back to ungrouped). Device-local singleton.

### Storage — thin, mirrors character-store/library-store
- **`lib/party-store.ts`** — CRUD parties under `documents/parties/*.json` + web shim.
- **`lib/session-store.ts`** — CRUD sessions (`documents/sessions/*.json`) and encounters
  (`documents/encounters/*.json`, `listEncounters(sessionId)`). Encounter mutations save immediately.
- **`lib/folders.ts`** and **`lib/dm-mode.ts`** each persist their one singleton JSON.
- **Character overwrite-on-import (#9)** is already keyed by the stable `CharacterFile.id`
  (`saveCharacter` writes `${id}.json`), so re-importing the same character overwrites. This release
  surfaces the outcome (an "updated existing" vs "imported" toast) and reuses the same id-keyed path when
  importing from the party selector; no schema change.

### UI — new routes + `features/dm/`
- Routes: `app/parties.tsx`, `app/sessions.tsx`, `app/session.tsx`, `app/encounter.tsx` (ids via params),
  plus the party overview reachable from a session. Menu routes to `parties`/`sessions` when DM Mode is on.
- `features/dm/`: `dm-theme.ts` (palette + `useDmPalette`), `parties-screen.tsx`, `party-editor.tsx`
  (multi-select member picker + import, present toggles, Enable), `sessions-screen.tsx` (party dropdown +
  session list), `session-screen.tsx` (active-encounter-pinned encounter list + Players button),
  `player-list.tsx` (party overview: collapsed vitals panel → expand to traits/level/prof),
  `encounter-screen.tsx` (allies/adversaries, options panel, log), `stat-pulse.tsx` (the heartbeat
  control), `combatant-panel.tsx`, `adversary-editor.tsx`, `encounter-log.tsx`.
- **`stat-pulse.tsx`** is a NEW compact control (not the HP heart-track, which is slot-specific). One
  sheet-style icon (heart/armor/stress/hope) owning a `scale` shared value: tap toggles increase/decrease
  mode; hold drives a repeating pulse to an activation point with a short dwell, accelerating over time,
  firing one `±1` per beat with a per-beat tick from the sfx engine (reusing `playSfx`/risers). Tapping
  the adjacent number opens the existing `NumberKeypad` to set an exact value (empty = no change). A
  press→release hold emits ONE log entry with the net change.
- Existing reused components: `AppScreen`, `ChamferBox`, `FitLine`, `RuneButton`, `PopupDialog`,
  `NumberKeypad`, `card-markdown` (log rendering), the sheet's stat glyphs/`primitives`, portrait well.
- **Folders in the roster** (`features/characters/roster-screen.tsx`): a "New folder" action; folders
  render as collapsible coloured group headers; a character's long-press menu gains "Move to folder"; a
  folder header long-press offers rename / re-roll colour / remove. Present in BOTH player and DM mode.

## Testing Decisions

Good tests here assert externally-observable reducer behaviour — vitals clamp to derived maxes and floor
at 0, present toggles and enable gate correctly, encounter indices number 1..N, `completeEncounter`
freezes exactly the current global state and leaves `party.global` intact, global-vs-local resolution
returns the right source per encounter status/sync, `formatStatLog` renders the "who/what/value" line, and
folder assign/rename/remove keep the index consistent. No test drives Reanimated/gesture motion or the
pulse animation — that is owner-verified on device, per project convention (`runekeep_verify_animations_manually`).

Modules under test: `lib/party.ts`, `lib/session.ts`, `lib/folders.ts` (new suites). Prior art:
`lib/leveling.test.ts`, `lib/rest.test.ts`, `lib/companion.test.ts`, `lib/library.test.ts`,
`lib/character-file.test.ts`. Data-integrity style pinning is not needed (no new static game data).

## Out of Scope

- Detailed adversary stat blocks / a bestiary (this release's adversaries are name + optional
  HP/thresholds/stress/description only; "later on the creation of adversaries will be more in detail").
- Initiative order / turn tracking, conditions, and dice — RuneKeep never rolls (core philosophy).
- Sharing/exporting parties, sessions or encounters over `.rkp`/NFC (characters still share as today).
- Multi-device party sync — all DM data is device-local.
- Adversary armor/hope tracks and player-only fields on NPCs.

## Further Notes

- The desaturated palette is a *rendering* choice only; disabling DM Mode never mutates or hides DM data —
  parties/sessions/encounters persist and reappear when DM Mode is re-enabled.
- Member max stats (maxHp, armor score, stress max, usable hope) are always derived live from each
  character file, so a party stays correct if a member levels up or re-equips between sessions.
- The pulse control's acceleration curve, dwell and tick cadence are tuning knobs to be felt on device.
