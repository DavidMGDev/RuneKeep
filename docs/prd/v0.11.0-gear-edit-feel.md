# v0.11.0 — Golden Gear Edit: feel pass

Second rework of the Golden Gear Edit mode shipped in v0.10.7, driven by on-device testing. Ten
targeted changes to how entering, arranging, and acting-on cards *feels*. Motion is owner-verified on
device (per the project norm); the pure maths (reorder, menu options) stays unit-tested.

## 1 — Arm ring + no enter over a transition
`carousel-geometry.ts` `EDIT_ARM_SHOW = 0.3`; `card-carousel.tsx` `EditArmRing` draws a progress ring
over the gear that fills with the hold-to-enter dwell, appearing only past 30% (so a plain gear scroll
or a category over-scroll shows nothing) and vanishing once edit mode is active. `osPush` cancels the
dwell the instant an over-scroll starts, and the dwell only fires `enterEdit` when `osDir === 0 &&
switching !== 1` — you can never enter edit over a transition.

## 2 — Softer, curved, denser row
Breath is ~60% faster (1500 → 940 ms) and 20% more opaque (0.20 → 0.24). `EDIT_SCALE 0.44 → 0.35`,
`EDIT_GAP 112 → 82` (≈2 px between cards) → **5 cards fully visible + 2 cut off**. New `EDIT_CURVE`
(edge droop) + `EDIT_TILT` (fan) give a gentle Balatro arc instead of a dead-flat row.

## 3 — Deeper dim + Edit Mode heading
`ExpandVeil` edit dim ~40% deeper (0.62 → ~0.92). New `EditHud`: an "Edit Mode" title in the empty top
band. (See #6 for its live count + Deselect All.)

## 4 — Smooth drag, edge autoscroll
The reflow gap (`hoverAnim`) **springs**, and each card's shift ramps continuously across it, so cards
glide instead of teleporting mid-drag. A `useFrameCallback` autoscrolls the row when the finger nears a
screen edge: the center 40% is a dead-zone; past it the speed ramps to a max reached *before* the very
edge (finger girth) and scales with the deck size.

## 5 — Exit returns to normal size
Entering edit now clears `grindProgress` (the gear-scroll shrink) in the dwell callback, so **exiting**
edit settles cards back to their normal expanded size instead of the small gear-scroll size.

## 6 — Live count + Deselect All
`EditHud` shows "X Cards" → "X/Y Cards" once a selection exists, with a subtle Deselect All pill (new
`deselectAll` on the carousel context).

## 7 — Modal icon wheel (radial rework)
The card-hold radial is rebuilt as a **modal** wheel of round icon buttons (`card-radial-menu.tsx`):
no rectangular panels, fades in, and **stays open** (finger stillness never closes it — the pan freezes
on `cardMenuOpen > 0.5`, so cards can't be selected behind it). Tap an icon to fire; tap the backdrop to
cancel. ~80% bigger (`CARD_MENU_RING 118`, `CARD_MENU_BTN 62`). Duplicate now inserts the copies right
after the last selected card, deselects, and scrolls the row onto them (imperative `CarouselApi`).

## 8 — Open on a lone unselected card
Holding an unselected card opens the wheel **only when nothing is selected** (that card becomes the
target); with a selection present, holding an unselected card does nothing.

## 9 — Partial vs full favorite
When the whole selection is already favorited the Favorite option flips to **Unfavorite** (`cardMenuOptions`
`allFavorited`); a partial selection favorites only the ones that aren't yet.

## 10 — Icons, not text
Every wheel option is an SVG glyph (duplicate / favorite / unfavorite / move / delete / send-NFC).

## Known follow-up
Dropping a **group** still snaps its trailing cards from the pile into the gap on commit (single-card
drops are teleport-free). Kept out of scope to avoid an async-render flicker; revisit if it reads badly.
