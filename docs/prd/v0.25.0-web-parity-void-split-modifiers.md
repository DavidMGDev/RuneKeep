# v0.25.0 — Web parity, the Void split, permanent modifiers, onboarding repairs

## Problem Statement

Three separate problems arrived together.

**The browser build is a second-class citizen and it shows.** It runs, but it does not feel like the
app. Lists that scroll on a phone do not scroll in Firefox, and dragging a card drags a ghost image
of it instead. Text you type into the character name stays the grey of a placeholder, so you cannot
tell whether it registered. Pop-up backgrounds sit offset from their own borders and button labels
truncate to an ellipsis rather than fitting. Focused cards fly to the top of the window instead of
its middle. Sound does not play at all. Trait chips showing the same number twice only respond on
one of the two. The Forge button glows as though the character is finished from the moment creation
begins. On a desktop there are no keyboard controls at all, so an app built for thumbs has to be
driven entirely by mouse.

**The Hope and Fear expansion contains content that is not in Hope and Fear.** The pack was built
from a pre-release sheet, and the printed release turned out to be a subset. Blood Hunter and
Summoner appear nowhere in any Hope and Fear PDF, yet the app ships them as Hope and Fear content.
Players therefore enable an official expansion and get material their table's book does not contain.

**Several things the player is told are wrong or missing.** Onboarding teaches the wrong side of the
HP track, points at the wrong graphic, and shows a greyed-out icon. Card creation puts new cards in
the wrong category and offers a Cancel button where cancelling makes no sense. Updating the app
blanks the portraits on the character list. The Blade card Vitality grants a choice of three
permanent boons and the app has no way to express any of it.

## Solution

One release that makes the browser indistinguishable from the tablet, splits the official expansion
along the line the printed books actually draw, and finishes the half-built parts of card creation,
modifiers and onboarding.

For the web, every fault is reproduced in a real browser first, in both Chrome and Firefox, and the
reproduction becomes a step in the release check so it cannot silently return. Desktop gains a full
keyboard control scheme with its own onboarding page.

For the expansions, everything absent from the Hope and Fear books moves to a new bundled official
expansion, **The Void**, presented as the beta that tested most of Hope and Fear's content but not
all of it. Existing characters keep working, because ids do not change and any character referencing
moved content silently gains the new expansion.

For the rest, modifiers grow the two capabilities the rulebook already assumes: a modifier can be
**permanent** (it survives being unequipped and only ends when the card is deleted everywhere), and
a card can ask the player to **choose** which boons it grants. Vitality is the first card to use
both. Onboarding is corrected and animated. Quick card creation gets its keyboard behaviour and
defaults fixed and is reused for character creation's experiences.

## Implementation Decisions

### Web faults are found in a browser, not reasoned about

Every web item is reproduced in `scripts/web-probe.mjs` before it is fixed, in Chrome and in Firefox,
and the reproduction stays as a step in the release check. This is the settled approach after v0.24.3
shipped four simultaneous web faults that `tsc`, `eslint` and `jest` all passed. Fixes asserted only
by reading code do not count as done.

Two engines are mandatory for this release specifically, because at least one reported fault (drag
ghosts) is Firefox-only: Gecko does not implement the `-webkit-user-drag` CSS property that the web
reset relies on. The cross-engine fix is to prevent the `dragstart` event rather than to style it
away, applied once in the HTML shell so it covers every image and every card without touching call
sites.

### Scrolling and gestures

The drag-to-scroll shim already treats `touch-action: none` as the marker for "a gesture owns this
pointer" and declines to interfere. Containers that are scrollable but not gesture-driven, the
subclass list among them, must therefore not carry that marker. The fix is to correct the marker on
the containers rather than to add exceptions to the shim, keeping one rule rather than a list.

### Keyboard control

A new pure module owns the mapping from a key event to an app intent, with no React and no platform
calls, so the whole scheme is unit-testable. It exports an `Intent` union (previous, next, focus,
unfocus, toggle, editMode, confirm, dismiss) and a resolver taking key, modifier state and the
current context (carousel, edit mode, dialog) and returning an intent or null. A thin web-only hook
attaches it to `window` and dispatches. Native never mounts the hook.

Shift is a modifier on movement intents rather than a separate intent: the resolver returns a step
count with the intent, so a caller does not need to know about Shift.

Context matters, so the resolver takes it: Space inside a text field must type a space, and Escape
inside a dialog must close the dialog rather than leave edit mode. The resolver returns null when a
text input has focus, except for Enter and Escape.

### Audio on web

The most likely cause of total silence is the browser's autoplay policy: an `AudioContext` created
before any user gesture starts suspended, and every later play is a no-op rather than an error. The
fix is to resume the context on the first pointer or key event, once, from the sound module itself so
no screen has to remember. This is checked in the probe by asserting the context state after a click.

### Dialog geometry

The offset background is a single-source-of-truth problem: the panel's border is drawn as vector
geometry and its fill as a view, and the two are sized from different boxes. One of them must derive
from the other. The border geometry is the harder constraint, so the fill derives from it.

Button labels get the same treatment as the existing auto-shrink control: measure, then shrink to a
floor, then wrap. Truncation to an ellipsis is removed as an outcome for buttons entirely, since a
control the player cannot read is worse than a control that is two lines tall.

### Card focus centring

Focus centres within the phone frame's viewport, never the browser window. This is the same class of
bug the tablet work fixed: any code reading window dimensions to position something inside the frame
is wrong by construction. The existing frame coordinate helpers are the correct source.

### Trait chips

Selection is currently keyed by the value shown. Two chips reading +1 therefore collide. Selection
becomes keyed by slot index, with the value carried alongside. This is a data-model fix, not a UI
fix, and it removes a whole class of duplicate-value bugs rather than the reported instance.

### The Void split

A new bundled official expansion is added alongside Hope and Fear. Both are official, both are off by
default, and both show read-only in the library.

The split is decided by evidence, not memory: a script compares every piece of app content tagged to
the expansion against the text of the four Hope and Fear PDFs and reports which side each belongs on.
That report is checked in, so the split can be re-run and re-argued later. Blood Hunter and Summoner
are already confirmed absent from all four books, with zero occurrences across cards, classes,
weapons and adversaries.

Ids never change. Only the expansion tag moves. This keeps every existing reference resolving, which
is the property that makes the migration safe.

Migration rule: on load, a character that references content now tagged to The Void gains The Void in
its enabled expansions. Without this, the split would silently strip a Blood Hunter character of its
class. This runs once and is idempotent.

### Hope and Fear ancestries become printed faces

Confirmed by diff before deciding: all twelve feature texts in the app already match the printed
cards word for word, so this is a fidelity change, not a correction. The six faces are cropped from
the publisher PDF at print resolution, and the cards become image cards like the base game's
ancestries.

The consequence is that the mixed-ancestry cross-out can no longer strike text blocks, because there
are no longer text blocks. It returns to the base game's model: measured per-line strike positions as
fractions of card height, in the same table and the same shape the base game uses.

Those positions come from `scripts/ancestry_marker.py`, which crops the faces, pre-fills the line
positions from the PDF's own text geometry, and writes a single self-contained HTML page for the
owner to verify and export. The pre-fill is not a convenience: it means the human step is checking
rather than measuring, which is both faster and more accurate. The generator is committed, because
the equivalent page for the base game was never committed and was lost.

**This release does not start until that export exists.** It is the one input that cannot be derived.

### Permanent and chosen modifiers

Two additions to the modifier model, both additive so existing cards are unaffected.

**Permanent.** A modifier may be marked permanent. A permanent modifier applies from the moment it is
first enabled and keeps applying regardless of the card's category or equipped state. It stops only
when the card is deleted from every category. The engine therefore resolves permanent modifiers from
the character's full card set rather than the equipped set, and card deletion becomes the single
removal path. The player is warned at the point of marking, not at the point of unequipping.

**Chosen.** A card may declare a set of options and a number to pick. Enabling the card prompts for
the choice; the selection is stored on the character file against the card instance, so duplicate
copies of a card can hold different choices. The engine reads the selection and applies only the
chosen options' effects. A card with no selection yet contributes nothing, which is the safe default.

Vitality is the first card using both: pick two of +1 Max Stress, +1 Max HP, +2 to both damage
thresholds, all permanent. Its green checkmark is the existing visual language for a card that cannot
be unequipped and does not count towards the domain card limit, and it is explained on first use.

History support falls out of the existing snapshot model: character history stores snapshots rather
than events, so undoing a Vitality choice restores the prior snapshot including the selection. No
replay logic is needed. The one requirement is that the selection lives on the character file so it
is inside the snapshot.

**Optional Rest Bonus** is a new modifier target consumed by the rest module, which already models
rest choices. The Elf ancestry stops describing it in prose and starts granting it.

### The modifiers panel

The +N, Fx and T controls move from a compressed row to a vertical layout using the space the panel
already has. This is a layout change with no model change. The permanent toggle joins them, with its
warning.

### Character creation

Experiences are created through the quick card flow, with the same advanced handover the card editor
has. The flow already funnels every creation path through one destination prompt, so experiences
inherit that.

Inventory becomes two choice groups presented like primary and secondary weapons: two carousels in
one step, Choice 1 offering the first pair and Choice 2 the second. Both offer "No items / Custom"
with the explanation. Items whose printed form is a consumable are added as consumables, which is a
data correction to the class inventory tables rather than a UI change.

Armor is added to the arsenal so stats can be enabled at creation, with onboarding recommending the
tidy-up afterwards rather than the app enforcing it.

The Forge button derives its enabled state from the existing completeness predicate. If that
predicate does not exist as a single expression today, it becomes one, since a button that lies about
readiness and a screen that cannot say whether it is complete are the same bug.

On short viewports the carousel shrinks to fit rather than overlapping what sits above it. The rule
is that the carousel takes the space that remains, never a fixed height.

### Quick card creation

The hold-to-pick-image gesture is currently composed so that a tap begins the hold animation. Tap and
hold become properly exclusive, with the hold's visual only starting after the recognition delay, and
the delay shortens.

Enter advances title to description and description to confirmation. The view scrolls the focused
field into view when the keyboard opens. On web the keyboard avoidance uses the visual viewport
rather than the native keyboard events, which is the source of the excessive raise.

The Ready step offers exactly two actions: keep editing, and create the card. The default content
type becomes Card, changeable only in advanced mode.

### NFC receive

The drop-from-top ceremony is replaced by a plain confirmation with a checkmark, naming the category
the player already chose in the destination prompt. The prompt stays; only the animation goes.

### Portraits surviving an update

Two mechanisms are in play and both need checking. Forged card snapshots are cached under a key that
includes the app version, deliberately, so that a release invalidates stale card art. That is correct
and stays, but it must become stale-while-revalidate: keep serving the existing bitmap while the new
one renders, rather than showing nothing until it does.

Character portraits are a different matter. They are referenced by URI on the character file, and a
URI pointing into a volatile location does not survive an update. Portraits must be stored in a
location the app owns and does not clear, with a migration that re-homes any existing portrait and a
graceful fallback when the source is genuinely gone. The exact volatile path is confirmed on device
before the fix, since guessing here would produce a migration that moves nothing.

### Onboarding

The HP page has its two sides swapped and gains the sheet's grow, shake and burst animation by
reusing the sheet's component rather than reimplementing it. The Circle Controls page uses the actual
circle control graphic. The wheel page uses the icon in its live colours. Pages advance on swipe as
well as tap, and page contents fade in.

Loading screens are restored. Their disappearance is treated as a regression from the onboarding work
and diagnosed as such rather than rebuilt from scratch.

## Testing Decisions

A good test here asserts external behaviour: what the player sees or what a pure function returns.
Tests that assert a component rendered a particular child, or that a hook was called, are not worth
writing, because they fail on every refactor and pass on every real bug.

The codebase's existing split is the right one and is followed: pure logic lives in modules with no
React and no platform imports, and those get unit tests. Anything requiring a browser gets a probe
step instead. Note the existing trap that a module importing the theme constants cannot be loaded by
Jest, so pure helpers must not reach for it.

**Unit tested:**

- The keybind resolver: every key, with and without Shift, in each context, including the rule that a
  focused text field swallows everything except Enter and Escape.
- Permanent modifier resolution: applies while equipped, applies while archived, applies while in the
  vault, stops only when the card is absent from every category.
- Chosen modifier resolution: nothing applied before a choice, only chosen options applied after,
  two instances of one card holding different choices.
- Vitality specifically, as the integration case of both, including that a history undo restores the
  prior selection and a re-equip preserves it.
- Optional Rest Bonus reaching the rest module and appearing as an extra choice.
- The expansion split: every piece of content lands on exactly one side, ids are unchanged across the
  move, and a character referencing moved content gains The Void on load.
- The inventory choice model: two groups, correct pairing, the skip option in both, consumables typed
  as consumables.
- Trait slot selection: two slots holding the same value are independently selectable.

Prior art for all of the above is the existing pure-module tests, in particular the modifier engine,
leveling, rest and character file suites, which are the closest in shape.

**Probe tested, in both Chrome and Firefox:**

- The subclass carousel scrolls by drag.
- No drag ghost appears on any card or image.
- Typed text in the character name renders in the active colour, asserted on the computed style.
- A pop-up's fill and border share bounds.
- A focused card's centre is within a tolerance of the frame's centre.
- The audio context reaches the running state after a click.
- Zero console errors across a full character creation walkthrough, which is the existing gate.

**Not machine tested, and stated as such rather than quietly skipped:** the hold-to-pick-image
gesture, NFC receive, an install on a physical phone, and every animation. Motion is verified by the
owner on a device, per the standing rule that screenshot testing animation produces confident
nonsense.

## Out of Scope

- Any form of sync, account or server. Storage stays local to the device.
- A desktop-specific layout. The phone frame is the desktop layout, by decision, and the keyboard
  scheme is what makes it comfortable rather than a reflow.
- Tauri or any packaged desktop binary.
- Digital dice, in this release as in every release.
- Rebalancing or reinterpreting any printed rule. Where the app and the book disagree, the book wins
  and the app changes.
- Content from Hope and Fear that the app does not already ship. This release moves and corrects
  content; it does not add books.
- iOS push, background sync, or anything requiring a native web capability Safari does not have.

## Further Notes

**The blocking input.** The ancestry strike positions are the only thing here that cannot be derived
from the repo or the PDFs. The marking page is built, verified in a browser, and pre-filled from the
PDF's own geometry, so the owner's step is confirming six cards rather than measuring thirty-six
lines. Nothing else in this release waits on anything.

**Two of the reported problems were not what they appeared to be.** The Hope and Fear ancestry text
was reported as outdated and is in fact identical to the printed cards, having been retranscribed in
v0.24.0. The instruction to move Blood Hunter and Summoner "into Hope and Fear" contradicted the rule
given in the same paragraph, and was confirmed to mean The Void. Both were checked before any work
was planned around them. The same standard applies to the remaining reports: the greyed-out inputs
and the missing loading screens are described by symptom, and the cause is established in a browser
before a fix is written.

**Scale.** This is a large release covering thirty-one reported items. The web parity work, the
expansion split and the modifier model changes are independent of one another and can land as
separate pull requests in any order. The ancestry work depends only on the owner's export. The
onboarding repairs depend on nothing.

**Design labour.** The onboarding pages and the modifiers panel layout are UI design work and go
through the design skill, per the owner's instruction, rather than being laid out ad hoc.
