# v0.10.3 — Custom content in creation & ADD GEAR (finishes B4)

Completes the deferred B4 from v0.10.2 (Feature 7 · Bug 1 · Bug 4). Built on the proven v0.10.2 data
model. **Guiding invariant: strictly additive — a character with no homebrew picks (`file.libraryCards`
absent) loads + renders byte-identically to before.** That invariant is unit-tested.

## The mechanism — embed, don't reference
When a homebrew card is picked (in creation or ADD GEAR), a **self-contained copy** of the `LibraryCard`
is stored on **`CharacterFile.libraryCards`**. So the character:
- renders + resolves effects with **no expansion installed**,
- **survives** the expansion being disabled or deleted,
- travels whole in a shared `.rkp` (Bug 4's data-safety).

Structural slot ids (`ancestryCardId`/`subclassCardId`/`communityCardId`/`domainCardIds`/`armorId`) may
reference these embedded ids.

## What shipped
- **Resolver (pure, tested):** `src/lib/library-embed.ts` (libraryCardById/Body/Effects, `armorSpecEffects`
  — bakes a custom armor's score + set-thresholds exactly like equipment). `character-file.ts`:
  `parseCharacterFile` accepts structural/domain ids backed by `libraryCards` (+ normalizes them via the
  shared `normalizeLibraryCard` trust boundary); `toSheetCharacter` labels the slot from the embedded card.
  `card-effects.ts`: `effectsForCardId`/`sourceLabelForCardId` resolve embedded cards.
- **Sheet render:** the forge-jobs memo forges each `libraryCard`; the deck-assembly memo resolves the
  structural trio + domain cards **catalog-first, then embedded** (so a custom card sits in its own slot →
  origin badges + ordering keep working), and places loose embedded cards (weapon/armor/inventory/generic)
  in the inventory deck. The `structItems` bail is unchanged for unknown ids.
- **Creation:** enabled-expansion content (`contentForCreation`) is appended to the ancestry / community /
  subclass / domains / armor / inventory decks; picking one sets the slot id (structural/armor) or a loose
  pick (inventory), and `forge()` embeds the picked cards + auto-enables armor/effect cards.
- **Library:** a per-expansion **Enabled / Disabled** toggle (`isExpansionEnabled`, `setExpansionEnabled`)
  — non-destructive: disabling only hides content from creation + ADD GEAR; characters keep their embedded
  cards.
- **ADD GEAR:** a **Homebrew** tab in `GearBrowser` lists loose custom cards from enabled expansions and
  embeds a fresh-id copy on tap (`onAcquireCustom`), auto-enabling armor/effect cards.

## Deferred (documented, out of scope)
- **Custom equipped WEAPONS** — (RuneKeep has NO digital dice; there is no attack roll.) The weapon-slot
  resolution + the damage calculator read the static equipment table via `weaponById`; a custom equipped
  weapon would need those to also resolve `file.libraryCards`. For now custom weapons are library/ADD-GEAR
  **display** cards (their while-equipped effects still apply when enabled), not the mechanical primary.
  Creation weapons stay built-in.
- **Custom standalone CLASSES** — need a mechanical chassis (2 domains, HP/evasion, subclass roster,
  starting kit) that was never designed. The class step stays built-in; custom subclasses attach to a
  built-in class via `className`.
- **Mixed-ancestry cross-out for a CUSTOM ancestry** — a single custom ancestry works; mixing one shows
  both features un-struck (the strike renders from bitmap geometry the built-ins have and custom text
  cards don't; a per-section line-through is a later polish). The disable data exists on the card.

## Validation
`tsc --noEmit` clean · **285/285 tests** (new: embed round-trip, reject-unknown, armor-effect baking,
label resolution, no-libraryCards-unchanged). Device-only checks: the on-sheet render of an embedded
homebrew character, and the creation flow end-to-end.
