# v0.12.3 — The Void polish + Edit-mode re-arrange fixes

Owner round-1 feedback on the shipped v0.12.2 Void expansion (4 items), all additive and gated exactly as
The Void already is.

## 1. Void class banners (issue 1)
The 6 Void classes rendered a placeholder stroked-rectangle SVG. Replaced with the owner's real banner
art (`assets/art/classBanners/void/*.webp`, converted from the provided JPGs). Wrapped in an `<Svg><Image>`
so it satisfies the existing `Banner: FC<SvgProps>` contract — no change to `ForgedCard`/`ForgedTextCard`
or the picker. Added a `*.webp`/`*.png`/`*.jpg` ambient module declaration so raster ES-imports typecheck.

## 2. Edit-mode re-arrange drop animation (issue 2)
Three fixes in `card-carousel.tsx`, all owner-device-verified (motion isn't screenshot-testable):
- **2a — reflow no longer cancelled.** A new `settling` shared value freezes the drag frame-callback on
  release; the drop is now strictly staged — settle the gap point + widen the gap to the block width
  (make-room), and only in *that* completion does the pile spread into the finished gap, then commit. The
  pile waits at the finger while the row makes room, so the carousel reflow always ends before the finger
  cards re-arrange in.
- **2b — 1-frame flash gone.** The committed-move `deselectAll()` was firing synchronously over the
  still-old deck, recomputing all cards to their OLD slots for a frame. It's now deferred to
  `finalizeCommittedDrop`, which runs only once the reordered deck is live (deck-change effect / safety net).
- **2c — cards drag + settle FLAT.** A new `editFlat` envelope suppresses the raised look (lift, scale
  bump, breathe, swipe-hint) from grab through settle, so a grabbed pile reads as deselected. A real move
  stays deselected; a no-op (dropped back home) re-raises the pile — but only after the settle animation
  ends. Selection membership (which drives the commit) is untouched; only the *visual* raise is gated.

## 3. Void card modifiers (issue 3)
Every Void card was analysed against the modifier engine's vocabulary. Only cards with a **permanent stat
passive** get an entry (identical convention to the base game, where most cards have none):
- `subclass-juggernaut-2-specialization` (Rugged: +3 Severe threshold) → `CATALOG_EFFECTS`.
- Earthkin/Stoneskin (+1 Armor Score & Damage Thresholds) → carried on the structured ancestry card (§4),
  gated to trait 1 so a mix drops it when crossed out.
- All other Void cards are activated/conditional/token abilities the engine doesn't model — no entry, played
  with the existing token/dice tools. One flagged gap (Eldritch Flesh scales with *marked* Stress) needs a
  new formula variable and is intentionally omitted.

## 4. Void ancestries rebuilt as structured cards (issue 4)
The 6 Void ancestries were opaque webp catalog cards with no region data → they never crossed out. Re-authored
"from scratch" as bundled `LibraryCard`s (`src/data/void-ancestries.ts`, two `sections` each) on the Void
expansion record, so they ride the generic custom-ancestry path: live forged rendering, markdown, and
**mixed-ancestry TEXT strike-through** on the sheet. The 6 image rows were removed from the catalog (catalog
regenerated 369 → 363). Ids are reused so any reference still resolves. `expansionCardCount` now sums record
cards + catalog-tagged cards (99) for the library + picker counts; the Void seed bumps to version 2 to refresh
installed copies in place (preserving the user's enable toggle).
