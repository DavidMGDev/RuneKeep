# v0.16.0 — DM Mode, second pass: usable heartbeats, fallen adversaries, libraries & polish

On-device testing of v0.15.0 DM Mode surfaced 18 fixes and features. This pass makes the heartbeat
controls actually usable, stops panels closing on mis-taps, reworks the player/adversary summaries to the
sheet's own colours, adds fallen-not-deleted adversaries, an adversary library, multi-select on lists, an
animated editable log, encounter restart, and a pile of flow polish.

## Problem Statement

The DM surface shipped but is fiddly in play: the stat pulses are hard to hit and read, every panel closes
if you miss a button, absent players don't read as absent, adversaries delete on a single tap (dangerous),
there's no way to reuse an adversary or keep a party's state between fights without entering one, and the
log is a static overlay that can't be edited or reordered.

## Solution

A second pass across the DM surface:
- **Heartbeat controls** get a single global increase/decrease toggle in the screen corner, filled
  sheet-coloured icons that grow above the finger while held, bigger numbers, and tighter layout.
- **Panels** stop closing on inside taps, gain smooth open/resize/close animations, and opaque backgrounds.
- **Adversaries** fall (name + "Fallen" + Recover) instead of vanishing; deletion needs multi-select +
  confirm or the X on a fallen unit; they can be saved to and spawned from a **library**.
- **Lists** (adversaries, allies, encounters, players) support hold-to-multi-select with move / delete /
  convert / presence actions and proper error handling.
- **Flows**: enabling a party toasts and turns the button into Sessions; a Sessions Menu button appears;
  a Party State button opens the overview without an encounter; starting a second encounter confirms and
  completes the first; completed encounters can Restart from party or encounter state; the encounter
  options panel gains rename + card-archive; toasts replace inline "start the encounter" text.
- **Log** becomes an animated 80% side panel; notes are editable and hold-drag reorderable; auto/stat
  entries are fixed-order but deletable via multi-select.

## User Stories

1. As a DM, I want a party's enabled state shown as a clear badge (not a lone dot), so that I can see it at a glance.
2. As a DM, I want enabling a party to toast confirmation and turn that button into "Sessions", so that I go straight to its sessions instead of hunting menus; and I want a "Sessions Menu" button above New Party (enabled once any party is enabled).
3. As a DM, I want tapping inside any DM panel/pop-up to do nothing (only the outside scrim or a real button acts), so that near-misses don't close the panel.
4. As a DM, I want the players panel readable and usable: filled sheet-coloured icons that grow above my finger when held, no per-stat ± sign, one global +/− in the screen corner, bigger numbers, taller entries with HP/Armor/Stress/Hope tightly grouped, a clear "expandable" affordance, scars reducing max Hope, and the trait row tighter but inset from the panel edges; the expanded view drops Armor and instead shows the count of unique domain cards (equipped + unequipped) across all categories.
5. As a DM, I want the log to be an animated 80%-width side panel that slides in/out, and I want to edit a log entry after creating it.
6. As a DM, I want adversaries to use the same filled-icon styling and global +/−, with a pencil (not a circle) to configure them.
7. As a DM, I want the same corner +/− control in the encounter, with the per-combatant config moved off the main tap area.
8. As a DM, I want hold-to-multi-select on adversaries, allies and encounters, with bulk move / delete / convert actions and clear error handling.
9. As a DM, I want adversaries to fall instead of delete: at 0 HP or on pressing X they become "name — Fallen" with a Recover button (back to half HP if they hit 0, or their prior HP/stats if X); units delete only via multi-select+confirm or the X on a fallen unit; players never delete; encounters can be duplicated.
10. As a DM, I want a single held adversary savable to a library, and a library button to add saved adversaries into an encounter, browsed in a player-summary-like list with expand.
11. As a DM, I want pop-ups (Complete encounter, etc.) to have an opaque fill inside the frame; and I want a completed encounter to offer Restart (choosing party or encounter state to continue from), reviving downed adversaries to half HP.
12. As a DM, I want a Party State button on the party UI to configure party stats without entering an encounter.
13. As a DM, I want a toast (not inline text) when I try to change member vitals before starting the encounter.
14. As a DM, I want a confirmation when starting an encounter while another is active — accepting completes the other and notes it in that encounter's log.
15. As a DM, I want absent party members shown greyed + labelled absent on sync interfaces, and a multi-select action to flip presence.
16. As a DM, I want the config, rename, log-note and options panels to animate in and resize smoothly, and the options panel to include Rename encounter and Open card archive (which returns to the encounter afterward).
17. As a DM, I want the adversary library to also spawn ally NPCs, and a multi-select action to convert allies↔adversaries carrying current stats (players can never become adversaries).
18. As a DM, I want auto/stat log entries fixed in order but deletable (via multi-select), and note entries reorderable earlier by press-and-hold.

## Implementation Decisions

- **Toast** (`components/toast.tsx`): a tiny event-emitter + `ToastHost` mounted once in the root layout; `showToast(msg, tone?)`. Used for enable-confirm (#2), locked-vitals (#13), and error handling on bulk ops (#8).
- **DmModal** (`features/dm/dm-ui.tsx`): a shared scrim+content wrapper that (a) absorbs inside taps via a content Pressable so only the scrim closes (#3), and (b) animates entrance/exit + resize with Reanimated (`FadeIn`/scale + `LinearTransition`), reused by NameDialog, AdversaryEditor, options, choosers (#16). PopupDialog gets an opaque fill behind its frame (#11) and the same inside-tap guard.
- **Global direction** (#4/#6/#7): the increase/decrease mode leaves StatPulse and becomes a screen-level `dir: 1|-1` with a corner +/− control (`DirectionToggle`). StatPulse takes `dir` as a prop, drops its per-stat mode + ± badge, uses filled sheet-coloured glyphs, and grows to ~2.2× (well above the fingertip) while held. Stat colours: HP/Stress `#C81B18` (heart / bolt), Armor `#DAA249`, Hope amber `#CC8F0F`. `StatGlyph` gains a `filled` variant.
- **Member panel** (#4/#15): taller, HP/Armor/Stress/Hope tightly grouped with bigger numbers; a visible chevron/hint for expand; absent members render greyed with an "Absent" tag; expanded view shows traits (tighter, inset) + level/proficiency + **domain-card count** (`domainCardCount(file)` in `dm-vitals.ts` = distinct domain-kind ids across `domainCardIds ∪ acquiredCardIds ∪ library domain cards`). Hope max already nets scars (`hope.total − hope.locked`); verified.
- **Fallen adversaries** (#9): `Combatant` gains `fallen?: boolean` + `recoverHp?: number`. `fell(c, viaX)` sets fallen and `recoverHp = viaX ? currentHp : ceil(maxHp/2)`; reaching 0 HP auto-falls; `recover(c)` restores hp=recoverHp, fallen=false. A fallen card renders name + "Fallen" + Recover; its X deletes. Live (non-fallen) units delete only through multi-select + confirm. Players are never deletable.
- **Multi-select** (#8/#17/#18): a reusable `useSelection` hook; long-press enters selection mode on a list (adversaries, allies, encounters, players, log). A selection action bar offers, per list: delete (confirm), move encounters to an existing/new session (`moveEncounterToSession`, reindex), duplicate encounter (`duplicateEncounter`), convert ally↔adversary carrying stats (`toAdversary`/`toAlly`, players excluded), flip presence, and (log) delete entries. Errors (e.g. deleting the last member — not allowed; players in a convert set) surface via toast.
- **Adversary library** (`lib/adversary-library.ts` + store): save a single `Combatant` template; list/add into an encounter as an adversary or an ally NPC. Browsed in a summary list mirroring the player panel.
- **Encounter lifecycle**: `startEncounter` confirms if another is active and completes it, appending a log note to the completed one (#14). `duplicateEncounter` copies to a new index. `restartEncounter(session, enc, party, source)` reactivates a completed encounter, pulling member state from party or `archivedGlobal` per the prompt, and revives downed adversaries to half HP (#11).
- **Log side panel** (#5/#18): slides in from the right at 80% width (Reanimated translateX). Note entries: tap to edit (prefilled NoteDialog), press-hold to drag earlier among notes. Auto/stat entries: fixed order, selectable for deletion only.
- **Options panel** (#16): adds Rename encounter (NameDialog) and Open card archive — routed to the existing gallery/archive with a return path back to the encounter (`/gallery?returnTo=/encounter?id=…`), the archive keeping full functionality.
- **Party**: a Party State button on the editor opens `/party-overview` (#12). Enable flips to a Sessions navigation button + toast (#2).

## Testing Decisions

Unit-test the new pure logic in `lib/session.ts` and `lib/party.ts`: fallen/recover HP math, ally↔adversary conversion preserving stats and rejecting players, `duplicateEncounter` numbering, `moveEncounterToSession` reindex, `startEncounter` completing a prior active with a log note, `restartEncounter` state-source + adversary revive, note-only log reorder leaving auto entries fixed. Adversary-library reducers (save/list/remove) get a suite mirroring `folders.test.ts`. No test drives Reanimated/gesture motion or the pulse — owner-verified on device (`runekeep_verify_animations_manually`). Prior art: `session.test.ts`, `party.test.ts`, `folders.test.ts`.

## Out of Scope

- Detailed adversary stat blocks / bestiary import (library stores the simple combatant shape only).
- Initiative/turn order, conditions, dice (RuneKeep never rolls).
- Sharing DM data (parties/sessions/encounters/adversary library) across devices.
- Reordering auto/stat log entries (fixed by design; only deletable).

## Further Notes

- The stat icons deliberately break the desaturated DM palette to carry their sheet colours — that's the point of #4.
- Card-archive-from-encounter reuses the existing gallery screen with a `returnTo` param; the gallery already owns share/filter/browse, so nothing there changes except honouring the return path.
