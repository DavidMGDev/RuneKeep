# v0.13.1 — Scar depletion, archive NFC share, title fit, Void ancestries in Add Gear, Martial Form

## Problem Statement

Device testing of v0.13.0 surfaced four defects and one missing subsystem:

1. Scarring a hope slot that is currently filled does not deplete the filled hope — the pip stays
   lit under the scar. The player expects the filled hope to explode (the normal deplete animation)
   the moment its slot gets scarred.
2. A dungeon master browsing the Card Archive cannot send a card to a player. Holding a
   fullscreened archive card should charge up with the same bottom-to-top gold fill used for
   enabling carousel cards, then open the NFC send panel for that single card. Nothing happens
   today.
3. Long weapon/armor titles ("Legendary Arcane-Frame Wheelchair", the Gauntlets family) truncate
   with "…" on forged cards, so item names read incomplete.
4. Void ancestries are missing from the sheet's "Add card from catalogue" browser even though every
   other Void content type appears there when The Void is enabled.
5. The Brawler's Martial Artist subclass has a Martial Form sheet (two stance picks per tier from a
   tiered stance list, powered by Focus tokens) — exactly the kind of own-page class mechanic that
   Druid Beastform and the Ranger Beastbound Companion got as dedicated interactive card
   categories. It was never implemented.

## Solution

1. Live sheet recomputes clamp hope to its usable (unscarred) count exactly like stress already
   does, so equipping a scar card over filled hope reduces active hope — and the existing burst
   animation plays the hope-dissipate effect on the depleted slot.
2. The archive's fullscreen card reader gains the carousel's hold-to-commit gesture and fill
   visual; completing the hold opens the existing NFC send panel with a catalog-reference payload
   the receiving phone resolves against its own bundled catalog (art included, zero payload
   weight). Weapons and armor travel as structured cards.
3. Forged card titles shrink-to-fit instead of ellipsizing.
4. The catalogue browser's ancestry tab merges expansion-record ancestries (the only Void content
   type not stored in the catalog), gated by the character's enabled expansions, added through the
   existing homebrew LibraryCard channel.
5. A new "Martial Form" card category appears for characters with the Martial Artist subclass
   (primary or multiclass): one interactive Focus-token card plus one card per martial stance at
   the character's tier or lower, single-stance-active semantics, locked to its category like
   Beastform. Assessment of the other five Void classes: Summoner Entities have no stat blocks
   (abstract, resolved via the summoner's own Spellcast rolls) and Warlock Favor / Witch / Blood
   Hunter / Assassin resources are per-card token piles — all covered by the existing
   dice-tokens-on-cards system; no further categories are warranted.

## User Stories

1. As a player with a filled hope slot, I want equipping a scar card to deplete that hope with the normal explode animation, so that the sheet state matches the rules and I see what I lost.
2. As a player, I want hope freed or reduced by any card edit (toggling, deleting, editing effects, level-up) to stay within my unscarred slots, so that hope can never sit inside a scarred slot.
3. As a player, I want removing a scar card to free the leftmost scarred slot without touching my current hope, so that recovery is predictable.
4. As a dungeon master, I want to hold a fullscreened card in the Card Archive and see it charge with the same gold fill as enabling a card on the sheet, so that the gesture feels like the rest of the app.
5. As a dungeon master, I want the completed hold to open the NFC send panel for that card, so that I can grant any official card to a player by tapping phones.
6. As a dungeon master, I want archive weapons and armor to be sendable the same way, so that loot handouts work too.
7. As a player receiving an NFC card, I want the received card to show its real catalog art when my app has that catalog card, so that the grant looks like the actual card.
8. As a user on a device without NFC (or in Expo Go), I want the hold gesture to tell me sharing is unavailable instead of silently failing, so that I understand why nothing opened.
9. As a player, I want long weapon and armor names to shrink to fit their card instead of ending in "…", so that item names are always complete.
10. As a player, I want every forged card title (generic, text, weapon, armor) protected from truncation, so that no custom or official name is cut off.
11. As a player with The Void enabled, I want Void ancestries to appear in the Add-card-from-catalogue ancestry tab, so that I can add them to my sheet like any other Void content.
12. As a player without The Void enabled for a character, I want Void ancestries hidden from that character's catalogue browser, so that expansion gating stays consistent.
13. As a Martial Artist Brawler, I want a Martial Form category on my carousel, so that my stances live in their own deck like a Druid's Beastform.
14. As a Martial Artist, I want one card per stance of my tier or lower, so that my available stances grow as I level.
15. As a Martial Artist, I want enabling a stance to disable the previously active one, so that only one stance is ever active — matching the rules.
16. As a Martial Artist, I want a Focus card with tappable token pips, so that I can track the Focus I rolled during my rest with physical dice.
17. As a Martial Artist, I want stances with sheet-mechanical effects (Steady's -1 Evasion, Immovable's +2 thresholds) to actually modify my sheet while active, so that the modifier engine stays the single source of truth.
18. As a Martial Artist multiclasser, I want the category to appear when Martial Artist is my multiclass subclass too, so that multiclassing works like Beastbound Companion.
19. As a non-Brawler, I want no Martial Form category on my ring, so that my carousel stays uncluttered.
20. As a player, I want Martial Form cards excluded from card sharing and immovable to other categories, so that special decks behave like Beastform.
21. As the owner, I want v0.13.1 released as a GitHub APK release after all tests pass, so that I can device-test immediately.

## Implementation Decisions

- **Scar depletion**: the four live merge sites that re-derive the sheet (level-up apply, file
  commit, card toggle, beastform auto-exit) clamp hope's active to total minus locked, mirroring
  the stress clamp and the file-load path. The card-toggle path already diffs old→new and bursts;
  the file-commit path gains the same burst call so effect edits that add scars also animate.
- **Archive hold + NFC**: the fullscreen CardReader attaches a LongPress raced with its existing
  tap/pan, replicating the carousel's fill (translucent gold view animating height from the bottom
  with a bright leading edge, arm haptic, commit haptic). Commit builds a `{ kind: 'card' }` .rkp
  payload and opens the existing NfcSendModal. Catalog cards travel as a minimal LibraryCard
  carrying a new optional `catalogId` field — the receiver resolves it against its own bundled
  catalog for art/identity (this is the "catalog-reference payload" deferred in v0.12.1). Weapons
  and armor serialize their structured equipment stats. The library's receive/rendering path
  learns to show catalog art for cards whose `catalogId` resolves. No NFC modules → a notice
  toast instead of the panel. Receive-into-sheet remains out of scope (unchanged from v0.10).
- **Title fit**: forged weapon/armor/text-card titles keep one line and gain shrink-to-fit with a
  minimum scale, matching the plaque label's existing pattern. FORGE_RENDER_V bumps so cached
  forged snapshots regenerate.
- **Void ancestries in Add Gear**: the gear browser's ancestry tab appends
  expansion-record ancestries from the creation-content resolver, filtered by the character's
  enabled expansion ids, and adds them via the existing custom-LibraryCard add channel (the same
  source and mapper the creation screen uses).
- **Martial Form**:
  - New data module with the 24 stances (tier, name, rules text verbatim from the extracted
    Brawler PDF data) and typed accessors, including an id-prefix guard used for category
    locking. Stances whose mechanics map to engine stats carry CardEffects; the rest are
    rules-text cards.
  - Category gate: subclass key `martial-artist` on the primary or multiclass subclass card,
    mirroring the Beastbound companion gate.
  - Deck: one interactive Focus card (six tappable pips, lock-free — current-value taps are
    gameplay, like companion stress) persisted as a new optional CharacterFile field, plus one
    forged text card per stance with tier ≤ the character's tier. Enabling a stance disables any
    other active stance (single-active, like Beastform's one-form rule).
  - Ring/label/icon registered alongside wildshape/companion; cards locked to the category,
    excluded from share/NFC id sets, excluded from add-card target lists.
  - Stance picks (two per tier) are tracked physically by the player; the app shows all stances of
    the character's tier like Beastform shows all forms — no level-up step. Known ceiling; a
    level-up picker can come later if wanted.
  - No categories for other Void classes (assessment above); their token mechanics ride the
    existing card token system.

## Testing Decisions

- Tests assert external behavior of pure modules only, following the existing suites
  (modifiers/character-file/library/rest).
- Scar clamp: extend the character-file scars suite is already green; add a regression test at the
  lib level only if the fix lands in a pure module (the clamp fix is in the sheet component —
  verified by type-check + owner device test, per the no-screenshot-motion rule).
- rkp/library: round-trip tests for the `catalogId`-bearing card payload through serialize/parse
  and normalizeLibraryCard.
- Martial Form data: integrity tests (24 stances, unique ids, tiers 1–4, six/seven/seven/four per
  tier, id-prefix guard) and gate logic tests with companion.ts's tests as prior art.
- Visual/motion items (hold fill, burst-on-scar, title shrink, Focus card) are owner
  device-verified.

## Out of Scope

- NFC receive directly into a character sheet (library receive remains the intake).
- A level-up stance picker for Martial Form (physical tracking this release).
- Interactive categories for Summoner/Warlock/Witch/Blood Hunter/Assassin (token system covers
  them; revisit with Void Phase C bespoke mechanics).
- Item 7 from the v0.13.0 request (message arrived truncated; still awaiting re-statement).

## Further Notes

Combo Strikes (base Brawler d4–d10 Combo Die) stays on the class card with physical dice/tokens —
it is a class feature, not the subclass sheet, and the owner's integration plan assigns
token/dice-trackable mechanics to the existing token board.
