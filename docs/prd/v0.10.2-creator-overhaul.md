# v0.10.2 — Creator overhaul, homebrew authoring & level-up fixes

Grilled + implemented autonomously. Batched by risk; each batch its own commit. Shipped: **B1–B3**
(10 of the 13 requested items). **B4 (custom content *consumed* in creation / ADD GEAR) is deferred** —
see the spec at the bottom, which is the load-bearing part of this doc.

## Shipped

### B1 — leveling fixes (`src/lib/leveling.ts`, `character-file.ts`)
- **Bug 2 (tier reset):** `advancementMarks` is now **per-tier**, stamped with `advancementMarksTier`.
  `advMarksUsed(file, key, tier)` reads a mark as 0 when its stamp ≠ the tier being evaluated, so the menu
  resets at each tier AND a stale stamp (pre-0.10.2 saves) reads as reset → **self-heals** characters
  soft-locked by the old campaign-wide counter. Multiclass capped at once-ever (single `multiclassName`).
  Subclass `slots:1` per tier is what makes *mastery* reachable (spec at T3, mastery at T4).
- **Bug 3 (subclass card):** the `subclass` advancement now pushes the next-tier sibling
  (`nextSubclassCardId`, same `subclass` family slug, tier+1) into `acquiredCardIds`. `parseCharacterFile`
  backfills saves that advanced the enum before this shipped.

### B2 — creator quick-wins + NFC trim
- **F1** Class cards in the Card Archive: new `class` gallery kind + a horizontal-pager `ClassReader`
  reusing `ForgedCard`/`ForgedTextCard` + `featurePages`.
- **F2** Per-section **Random** button (text, no emoji) in each creator deck + traits; Experiences stay manual.
- **F3** **Skip** cards end the weapons/armor/inventory carousels (`weaponsSkipped`/`armorSkipped`/
  `inventorySkipped`); in-creation custom-inventory authoring removed (homebrew items come from the Library).
- **F9** NFC = single card only: dropped whole-expansion send, restricted Golden Gear "Send NFC" to exactly
  one card, added per-card send in the Library, receive rejects non-card payloads.

### B3 — custom-card authoring overhaul (`library.ts`, `card-editor.tsx`, `library-screen.tsx`)
- **F5** content type chosen up front via a New-card `TypeChooser`.
- **F6** `weapon` / `armor` / `inventory` content types + custom type label. `LibraryCard` gains
  `weapon?: WeaponSpec` / `armor?: ArmorSpec` (def-shaped, full mechanical) so B4 can make them work in creation.
- **F8** the single body box → add/delete/reorder `sections[]` with a Bold/Italic/bullet toolbar
  (`SectionsField`, opt-in via `sectioned` so experiences/notes/sheet cards are unchanged). Composed to a
  markdown `text` fallback via `composeSections` (pure, in `card-markdown.ts`, unit-tested).
- **F4** ancestry cards = two fixed feature `sections` + `ancestryEffectTrait` (which line keeps the passive).
  This is the *data* the mixed-ancestry cross-out needs; the *render* is wired on the sheet in B4.

## DEFERRED — B4: custom content consumed in creation / ADD GEAR (Feature 7, Bug 1, Bug 4)

Not shipped because it can't be done safely without on-device verification. The data model + buckets
(`contentForCreation`) are ready; this is pure wiring. Two independent slices:

### Slice A — loose custom cards via ADD GEAR (lower risk)
`file.customCards` entries **already render** as ForgedCards (`redesigned-sheet.tsx` `customCardJobs`, split
by `target`). So a custom **generic / inventory / weapon / armor** card can be added to a character by
**embedding it into `file.customCards`** (a `CustomCardDef` = `ExperienceDef` + `target`) — it survives the
expansion being disabled/deleted and travels in the shared `.rkp` (Bug 4's data-safety, satisfied by embed).

### Slice B — structural custom slots in creation (higher risk — the memory-flagged hard problem)
Custom **ancestry / subclass / class / domain** as creation *picks* (Feature 7, Bug 1) needs the sheet's
resolution layer to accept non-catalog ids. Blockers found:
- `parseCharacterFile` (`character-file.ts:213-217`) **throws** on any `subclassCardId`/`ancestryCardId`/
  `communityCardId`/`domainCardIds` not in the catalog — load-bearing for **every** existing character.
- The deck-assembly memo (`redesigned-sheet.tsx:759-761`) **bails to empty** if the structural trio doesn't
  resolve via `cardById`.
- `toSheetCharacter` degrades (empty labels) but doesn't crash.
Required: an embedded custom-cards store on the `CharacterFile` that `cardById`/the resolver/`parseCharacterFile`
consult BEFORE the catalog (strictly additive: no-custom-content path stays byte-identical), an
expansion-picker pre-step in creation gated on ≥1 enabled expansion, and the mixed-ancestry strike rendered
from `sections` (line-through the crossed feature) instead of the built-ins' measured bitmap geometry. Custom
standalone **classes** additionally need a mechanical chassis (2 domains, HP/evasion, subclass roster,
starting kit) that was never specified — out of scope until designed.
