# v0.13.2 — custom-ancestry cleanup, catalog sourcing, redundant catalog button, library buttons, and always-on NFC card receiving

## Problem Statement

Five rough edges surfaced while playing and sharing homebrew:

1. **Custom ancestry authoring exposes a nonsense knob.** Creating a custom ancestry shows a
   "Passive on feature line" chooser (Feature 1 / Feature 2). It claims to decide "which feature stays
   active when mixed," but in the mixed-ancestry system that is already decided by *selection order*
   (the first-picked ancestry keeps Feature 1, the second keeps Feature 2). The knob is confusing and
   contradicts how The Void's bundled ancestries behave. Authors should not have to think about it.

2. **Custom-expansion cards do not appear in "Add card from catalog."** A player who enabled a custom
   expansion *globally* (after a character was already created) cannot find that expansion's **domain**
   cards in Add Gear. The same gap affects community / subclass / class cards. Only ancestries were
   taught to read expansion-record content (v0.13.1); every other category still reads the bundled
   catalog only, so record-stored homebrew silently never shows up.

3. **The "Add Card" badge lacks the catalog shortcut.** The float-menu "New Card" flow offers an
   "Add card from catalog" button at the bottom; the sheet's "Add Card" badge opens the same authoring
   flow but hides that button, so the two entry points are inconsistent.

4. **Library action buttons are unreadable, and NFC lives in the wrong place.** The card-library bottom
   buttons truncate ("Impo…", "Rece…", "New Exp…", "Delete E…") because several wide uppercase labels
   share one flex row with no auto-shrink. Separately, NFC *receiving* currently lives on the library
   screen, but receiving a shared card belongs on the character sheet (a DM taps a card to a player who
   is looking at their sheet). There is no NFC receiving on the sheet today, and a player can be left
   unsure whether their phone is even listening.

5. **A received card just appears with no ceremony.** When a card arrives over NFC it should feel like
   it *lands* on the sheet, not blink into a list.

## Solution

1. **Remove the "Passive on feature line" field.** Custom ancestries derive their crossed-out feature
   purely from mixed-ancestry selection order, exactly like Void ancestries. The mechanical passive is,
   by convention, tied to **Feature 1** (as Void's Earthkin already is), so it drops when Feature 1 is
   the crossed-out half. The section editor's smart Feature 1 / Feature 2 organization is unchanged.

2. **Read record-stored custom content into every catalog tab.** The gear browser merges globally
   enabled custom-expansion cards for domain, community, subclass, and class the same way it already
   does for ancestry — custom domain names appear as selectable chips, and any record card is added as
   an embedded copy.

3. **Show the catalog button in both add-card flows.** The "Add Card" badge flow renders the same
   "Add card from catalog" button the float-menu flow does.

4. **Readable buttons + always-on sheet NFC receiving.** Library buttons auto-shrink to fit (never
   truncate). The library's "Receive NFC" button is removed — expansions are shared via Import / Share
   `.rkp`, and single-card NFC receiving moves to the character sheet, where it is **always listening**
   except while a blocking interface is open (level up, rest, add card / add gear, edit mode, the
   incoming-damage panel, or the cards/categories panel). It is **never** blocked by card view state
   (expanded, compacted, fullscreen, category over-scroll, or icon animations), and the gate can never
   latch: it is derived from live panel state that the device-back button always unwinds, so a player
   is never softlocked out of receiving.

5. **A landing ceremony for received cards.** On receipt, a confirmation panel fades in and the carousel
   eases to compact; on accept, the card descends from the top of the screen with a light particle
   sparkle and settles into the center of the hand as the focused card, committed without a flash (the
   same flicker-free-commit principle Golden Gear Edit uses).

## User Stories

1. As a homebrew author, I want the custom-ancestry editor to not ask me "Passive on feature line," so that I am not confused by a choice that has no real effect.
2. As a homebrew author, I want my custom ancestry to mix with another ancestry exactly like the official Void ancestries do, so that the correct feature is crossed out based on the order they were chosen.
3. As a player, I want a custom ancestry's passive to switch off when its Feature 1 half is crossed out in a mix, so that the mechanics match what the card visibly shows.
4. As a player, I want the section editor to keep organizing Feature 1 / Feature 2 by their position on the card, so that authoring ancestries still feels smart and predictable.
5. As a player who enabled a custom expansion globally, I want its domain cards to appear in "Add card from catalog," even on a character created before I enabled it.
6. As a player, I want custom community, subclass, and class cards from an enabled expansion to appear in their respective catalog tabs too, so that no homebrew content is silently missing.
7. As a player, I want a custom domain's name to show up as a selectable domain chip in Add Gear, so that I can filter to it.
8. As a player, I want to add a custom-expansion card from the catalog and have it embedded on my character, so that it survives even if I later disable or delete the expansion.
9. As a player, I want the sheet's "Add Card" button to also offer "Add card from catalog," so that both ways of adding a card behave the same.
10. As a player, I want the card-library buttons to show their full labels, so that I can tell Import from New Expansion from Delete Expansion at a glance.
11. As a player, I want the redundant library "Receive NFC" button gone, so that receiving happens in the one place it makes sense (my character sheet).
12. As a dungeon master, I want to tap a card from my phone to a player's phone while they are on their character sheet, so that I can hand them a card in seconds.
13. As a player, I want my sheet to always be ready to receive an NFC card, so that a DM can tap me a card whenever I am just looking at my sheet.
14. As a player, I do not want NFC receiving to fire while I am in the middle of leveling up, resting, adding a card, or editing, so that a stray tap never interrupts a focused task.
15. As a player, I want NFC receiving to keep working while my cards are expanded, compacted, fullscreen, or mid-scroll, so that a normal viewing state never locks me out.
16. As a player, I never want to be softlocked out of receiving because a panel was opened once and left in a bad state, so that receiving always comes back by simply closing what is open.
17. As a player, when a card is tapped to me I want a confirmation before it is added, so that I stay in control of what lands on my sheet.
18. As a player, I want the carousel to ease into compact when the receive panel appears, so that the arrival feels calm and deliberate.
19. As a player, I want the received card to fall in from the top with a subtle sparkle and settle into the center of my hand, so that receiving feels like a real handoff.
20. As a player, I want the carousel to update without any flash or flicker when the received card is committed, so that the ceremony looks polished.
21. As a dungeon master sharing an official card, I want the receiving phone to show the real card art, so that the player gets the true card and not a plain text copy.
22. As a player receiving a homebrew card, I want its authored art/body preserved, so that custom cards arrive intact.
23. As a player, if someone taps me a whole character or expansion instead of a card, I want a clear message rather than a broken animation, so that the wrong payload fails gracefully.

## Implementation Decisions

### Item 1 — custom ancestry field removal
- **Remove** the "Passive on feature line" control from the custom-ancestry content config in the
  library authoring screen. The `ancestryEffectTrait` data field stays on `LibraryCard` (additive,
  harmless) but is no longer author-facing.
- **Default the effect gate to Feature 1.** In the card-effects resolver, a custom ancestry in a mix
  drops its passive when the crossed-out feature equals its effect trait, treating a missing trait as
  `1`. This matches Void's Earthkin convention. No change to the visible strike (already order-driven
  via `mixedCrossedTrait` + `featureSectionIndexes`).

### Item 2 — catalog sourcing for custom expansions
- The gear browser already collects *globally enabled* custom-expansion cards in one effect but only
  buckets ancestry + loose homebrew. Bucket the remaining record content types (domain, community,
  subclass, class) from the same list and merge each into its tab.
- Custom domain names union into the domain chip list; the domain carousel merges catalog + record
  domains for the selected domain.
- The "Select this card" handler resolves the centered id against the full record set and routes any
  record card through `onAddCustom` (embed), catalog cards through `onAdd` — one unified lookup.
- No per-character snapshot change is needed: the record path already includes non-official
  expansions whenever they are globally enabled.

### Item 3 — catalog button in the Add-Card flow
- The new-card flow hides the catalog button only when `onAcquire` is absent, and the sheet nulls
  `onAcquire`/`onAcquireCustom` for the `'card'` entry. Pass them through for the `'card'` entry so the
  button appears; the `'card'` vs `'menu'` entry distinction remains for category defaulting.

### Item 4 — library buttons + NFC relocation
- **Buttons:** `RuneButton` gains `adjustsFontSizeToFit` + a minimum font scale so any label shrinks to
  fit its flex column instead of tail-truncating. Removing the "Receive NFC" button also widens the
  remaining hub buttons.
- **Remove library receiving:** delete the "Receive NFC" button, its one-shot receive modal, the
  `nfcReceive` state, and the received-cards-into-`exp-received` handler. Expansion sharing stays on
  Import / Share `.rkp` and the per-card NFC *send* button is untouched.
- **Sheet receiving (always-on):** a controller component mounted inside the carousel + float-menu
  providers (the `SheetBackGuard` precedent) runs a persistent `receiveNfc()` loop while a derived
  `nfcReceiveActive` predicate is true. The predicate is a **pure function** of panel flags:
  - **Blocks** on any open interface: `floatKind !== null` (level / rest / add-card / add-gear /
    modifiers / cards), `damageOpen`, `cardInfoId`, `editCardId`, `emptyPanel`, `leaveConfirm`,
    `nfcSend` (don't receive while sending), an in-flight receive, and carousel `editing` (Golden Gear
    Edit).
  - **Never blocks** on `machineState` (compact / expanded / fullscreen), `switching` (over-scroll),
    or any icon/rise animation.
  - Softlock-proof because every blocking flag is unwound by the existing device-back guard and the
    transient confirms self-close.
- The loop cancels the in-flight read when the predicate goes false and re-arms when it returns true.

### Item 5 — receive ceremony
- Received content is validated: only `kind: 'card'` proceeds; character / expansion payloads raise a
  notice.
- A confirmation overlay (chamfer panel, gold-on-ink, in the app motion language) fades in and the
  carousel eases to compact.
- On **accept**, the card art descends from above the screen with a small deterministic particle field
  (plain `Animated.View` / SVG driven by one Reanimated progress value — no Skia in this project) and
  settles at the carousel center; the commit happens under the descending overlay so the array change
  never shows a wrong-order or empty frame (the Golden-Gear-Edit flicker-free-commit principle).
- **Commit routing:** a card carrying a `catalogId` that resolves to a bundled catalog card is acquired
  as that catalog card (true art); otherwise it is embedded as a self-contained library-card copy.
- On **decline**, the overlay fades and nothing is committed.

## Testing Decisions

Good tests here assert *external behavior* — the resolved effect of a mix, the routing of a payload,
the boolean gate — not rendering or animation internals (motion is owner-verified on device, never
screenshot-tested).

- **Item 1:** extend `card-effects.test.ts` — a custom ancestry with effects but *no*
  `ancestryEffectTrait`, picked second in a mix (Feature 1 crossed out), resolves to **no** effects;
  picked first (Feature 2 crossed out) keeps its effects. Prior art: the existing Earthkin mixed-effect
  assertions in the same file.
- **Item 4:** a new pure `nfcReceiveActive(flags)` helper gets a focused unit test — true on the bare
  sheet and while cards are expanded/compact/fullscreen/switching; false for each blocking flag. Prior
  art: the small pure-logic tests under `src/lib` and `src/features/character-sheet`.
- **Item 5:** unit-test the payload router (`card` → commit path, `character`/`expansion` → notice) as a
  pure function; the animation itself is device-verified.
- Regression: the full existing suite (rkp round-trip, library normalize, carousel-categories, martial
  form) stays green.

## Out of Scope

- Animating the *expanded* arc to physically slide cards apart with a per-slot tween; the ceremony
  delivers the flicker-free commit + overlay landing, not a bespoke arc-insertion tween.
- Resolving `catalogId` to catalog art in the general sheet render pipeline (received official cards go
  through the catalog-acquire path instead).
- iOS / Expo Go NFC (unchanged — native-module gated; the APK carries them).
- Re-syncing an existing character's per-creation expansion snapshot (unnecessary — custom expansions
  reach the catalog browser purely via global enablement).

## Further Notes

- The Void assessment from v0.13.1 stands: only Martial Artist earns a special category; nothing here
  revisits it.
- Any forged-card *visual* change must bump `FORGE_RENDER_V`; none of these items change forged-card
  rendering, so no bump is required.
