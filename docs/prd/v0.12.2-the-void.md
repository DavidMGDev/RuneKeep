# v0.12.2 — "The Void" official expansion

The full content integration promised by the v0.12.0 groundwork. "The Void" ships as a bundled
**official expansion**: additive, OFF by default, and unable to alter the base game until a player opts
in — globally in the Card Library or per-character at creation.

## Problem

v0.12.0 extracted all of The Void (art + data) and shipped per-expansion toggles, but the content itself
wasn't playable: no Void classes/domains/ancestries in creation, no per-character expansion selection, and
no place to see official content in the library. The owner's follow-up: make it all real and release with
**every** Void feature, without ever risking the base game.

## Solution

The Void is a hard-coded official `Expansion` record whose **cards live in the catalog** (each tagged
`expansion: 'void'`) and whose **classes live in class-data**. A single gating helper (`catalogFor`) keeps
tagged cards invisible unless their expansion is enabled. Enablement is two-layered: a global read-only
toggle in the Card Library's new **Official Expansions** section, and a per-character **expansion picker**
shown when creation opens. The picked set is stored on the character (`enabledExpansionIds`) so heroes are
self-contained.

## Shipped

### Content (verbatim from the publisher PDFs, original placeholder card art)
- **6 classes**: Assassin (12 EV / 5 HP), Witch (10/6), Warlock (11/5), Blood Hunter (11/6, **all three
  subclasses**), Summoner (10/**6**), Brawler (10/6). Each with foundation features + Hope feature, class
  inventory, and a forged class banner.
- **2 domains**: Blood and Dread (shared across the Void classes), full card sets.
- **6 ancestries, 6 communities, 6 transformations** — 99 catalog cards tagged `void`.

### Gating architecture
- `src/lib/expansions.ts` — `catalogFor(ids)` (base cards always, tagged cards only when enabled),
  `classExpansion(key)`, `isOfficialExpansion`, `VOID_META`, and idempotent `seedOfficialExpansions()`.
- `isEnabledForCreation` — official packs default **disabled**, custom packs default **enabled**.
- Base catalog cards are untagged, so a base-only hero resolves byte-identically to before (verified).

### Creation expansion picker (`src/features/create/expansion-picker.tsx`)
An on-brand, non-dismissing modal on creation entry: **Base Game** locked on, one toggle row per installed
expansion (The Void listed as "Official"). The picked set gates every class / ancestry / community / domain
/ subclass list in the creator and is written to `CharacterFile.enabledExpansionIds` (omitted entirely for
base-only heroes, preserving back-compat).

### Card Library — "Official Expansions"
A read-only section above "My Expansions", always first. The Void shows there with its real card count
(read from the catalog, since its stored `cards` array is empty), a global enable toggle, and no
edit/delete/add-card affordances.

### Sheet — Add Gear / Add Card + arsenal
- The gear browser gates class/domain/ancestry/community/subclass by the character's `enabledExpansionIds`.
- **Transformations get their own category/tab**, sitting beside ancestries in the arsenal — present in Add
  Gear, absent from character creation (you grow into them).
- Multiclassing is gated to the character's enabled expansions (a base hero can't multiclass into a Void
  class).

### Card Archive
Every Void card is browsable (Void class cards under Class, catalog cards inline), with a new **Forms**
filter chip for transformations.

## Testing

- `src/lib/expansions.test.ts` (new) — guards the load-bearing invariant: base-only creation sees every
  base card and **zero** Void cards; enabling The Void un-gates exactly the Void cards; `classExpansion`
  tags only Void classes; official = off-by-default, custom = on-by-default.
- Existing `data-integrity` extended for the new `transformation` kind.

## Out of scope
- Bespoke per-class mechanics beyond cards/tokens/stances (Crimson Rite dice math, summon automation) — the
  cards carry the rules text; mechanics are played with the existing token/dice/own-category tools.
- Recraft-processed illustrated banners (placeholder art shipped, per owner's choice A1).

## Checks
