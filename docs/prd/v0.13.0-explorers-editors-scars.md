# PRD — v0.13.0: Explorer filters, editor safety, ancestry sections, Void subclasses, card typography, picker-at-roster, level-up traits, empty carousel, Scars

## Problem Statement

Ten pain points reported by the owner after playing with v0.12.5:

1. The Card Archive can't filter Void cards — only the 9 base domain chips exist, and Void cards ignore the global expansion toggle entirely.
2. Tapping between the text fields of the "New Expansion" popup (and card-creation popups) closes the popup and destroys everything typed.
3. Custom ancestries force "Feature 1"/"Feature 2" to be the first two sections — no description-first layout, no re-arranging.
4. Custom subclasses can't be attached to the six Void classes — the class picker only offers the 9 base classes.
5. Custom/forged card text looks nothing like official Daggerheart cards: thin titles, tiny body text, huge section gaps.
6. The "Choose Expansions" panel appears late (on top of an already-mounted creation screen), the Base Game row looks deselectable when it isn't, and custom expansions list before The Void.
7. Pressing the Favorites star with no favorites silently no-ops (negative sound only) — no explanation.
8. Leveling into 5 or 8 (tier starts) should clear trait marks, but the level-up dialog still shows the old marks as locked, so tier trait increases can't be assigned during the dialog that matters.
9. Opening/expanding an empty card carousel gives a dim screen, sound effects, and a blank hand — nothing telling the user what to do.
10. No Scar support: Daggerheart scars permanently disable hope slots, and there is no way to model that as a card effect.

## Solution

One release (v0.13.0) fixing all ten:

1. Archive derives domain chips from the expansion-gated catalog and hides cards of globally-disabled expansions; enabling The Void globally makes Blood/Dread chips appear and their cards filterable everywhere.
2. Creation/authoring popups only close via their Cancel button — panels catch their own taps; backdrops never dismiss a form holding user input.
3. Ancestry sections become free-form: a deletable description section by default, plus two mandatory feature sections that can be re-arranged anywhere; the topmost feature is always "Feature 1" (names auto-swap on reorder), and mixed-ancestry strikethrough/effects follow the features wherever they sit.
4. The subclass (and class) authoring picker lists all 15 classes including the Void six.
5. Custom and forged card typography is re-set against the official card scans: black-weight titles, larger body, tight paragraph gaps, left alignment, bold-italic section leads.
6. The expansion picker moves to the character-select screen: it opens when "New character" is pressed and creation loads only after Continue. Base Game renders visibly locked (greyed, "Always on"). Order: Base Game → The Void (official) → user expansions. Picker rows scroll.
7. Empty-favorites star press shows a toast: "Add a card to favorites!".
8. The level-up dialog treats trait marks as cleared when the level being entered is a tier start (5, 8 — and 2), matching what applyLevelUp commits.
9. Any attempt to expand/edit an empty carousel category suppresses the dim/sfx/gear-grow and instead fades in a panel — "There is nothing here / Switch to a category or create the first card?" — with three stacked buttons: Change category (opens a modal list of categories that have ≥1 card), Add from Catalogue, Create Card.
10. Scars ship as a card effect: a new "Misc" group in the effects editor with a formula-free "Add Scar" option. Each equipped scar card scars one hope slot from the right (greyed, unsaturated, disconnected, unusable). Scar count is flat — removing any scar card frees the leftmost scarred slot. At 6 scars the entire character sheet desaturates (still functional) until a scar card is unequipped.

## User Stories

1. As a player using The Void, I want Blood and Dread filter chips in the Card Archive, so that I can browse Void domain cards like any base domain.
2. As a player who disabled The Void globally, I want Void cards hidden from the Archive, so that content I opted out of doesn't clutter browsing.
3. As a player who enabled The Void globally, I want Void cards to appear and be filterable in every card explorer, so that global enablement means what it says.
4. As a homebrew author, I want the library's domain quick-picks to include Blood/Dread when The Void is enabled, so that I can author cards for those domains.
5. As a homebrew author, I want the New Expansion popup to survive taps between its text fields, so that I never lose typed metadata.
6. As a homebrew author, I want creation/authoring popups to close only via Cancel, so that dismissal is always deliberate.
7. As a homebrew author, I want the card-type chooser to not vanish when I tap between its chips, so that choosing a type isn't fragile.
8. As an ancestry author, I want a description section first by default, so that my ancestry reads like official ancestry cards.
9. As an ancestry author, I want to delete the description or add more sections, so that layout is mine.
10. As an ancestry author, I want to move Feature 1/Feature 2 anywhere among the sections, so that features aren't chained to the top.
11. As an ancestry author, I want feature names to auto-swap so the upper feature is always "Feature 1", so that naming stays canonical without my bookkeeping.
12. As an ancestry author, I want the two feature sections to be mandatory and undeletable, so that mixed-ancestry mechanics always have two features to work with.
13. As a player with a mixed ancestry, I want the crossed-out feature to be struck through correctly even when features were re-arranged, so that the card reads right on the sheet and in creation.
14. As a player with an ancestry passive, I want the passive to stay gated to the correct feature after re-arranging, so that effects don't silently break.
15. As a homebrew author, I want Void class chips in the subclass creator, so that I can author subclasses for Assassin, Witch, Warlock, Blood Hunter, Summoner, and Brawler.
16. As a creating player, I want my custom Void-class subclasses offered during creation when I pick that class, so that homebrew integrates fully.
17. As a reader of custom cards, I want titles with the same black weight as official cards, so that custom cards feel official.
18. As a reader of custom cards, I want larger body text with tight paragraph spacing, so that cards are legible and dense like the originals.
19. As a reader of custom cards, I want section names set as bold leads inline with their text, so that features scan like "Thick Skin: …" on official cards.
20. As a card author, I want the editor preview to reflect the new typography live, so that what I compose is what ships.
21. As a player creating a character, I want to choose expansions on the character-select screen before creation loads, so that the picker isn't racing an already-visible creation UI.
22. As a player creating a character, I want the Base Game row visibly locked, so that I don't try to deselect it.
23. As a player creating a character, I want expansions ordered Base Game → The Void → my expansions, so that official content leads.
24. As a prolific author, I want the expansion picker and character roster to scroll, so that many expansions/characters stay reachable.
25. As a player with no favorites, I want a toast saying "Add a card to favorites!" when I press the star, so that the button's silence isn't confusing.
26. As a player leveling into 5 or 8, I want all trait marks unmarked inside the level-up dialog, so that I can spend my tier trait increases immediately.
27. As a player opening an empty card category, I want no dim/sfx/gear-grow but a "There is nothing here" panel, so that the app guides me instead of showing a blank hand.
28. As a player on the empty panel, I want a "Change category" button listing only categories with at least one card, so that I can jump somewhere useful.
29. As a player on the empty panel, I want Add from Catalogue and Create Card buttons, so that I can fill the category on the spot.
30. As a player on the empty panel's category list, I want everything behind the panel non-interactable, so that taps can't leak through.
31. As a card author, I want a "Misc" effects group with a formula-free "Add Scar" option, so that scar cards are one tap to define (and one tap to remove).
32. As a scarred player, I want my rightmost available hope slot greyed, unsaturated, and disconnected from the gold rule, so that a scar is visually a dead slot.
33. As a scarred player, I want scarred slots unusable (hope can never fill them), so that the mechanical cost is real.
34. As a scarred player, I want scars to stack right-to-left one per equipped scar card up to all 6 slots, so that repeated scarring works.
35. As a scarred player, I want unequipping any scar card to free the leftmost scarred slot, so that scar count is flat and order-independent.
36. As a player at 6 scars, I want the entire sheet desaturated (but functional) until a scar card is unequipped, so that total scarring lands with weight.
37. As a player sharing cards, I want scar effects to travel with .rkp/NFC card sharing, so that scar cards work everywhere.

## Implementation Decisions

- **Global enablement helper**: a new pure helper in the expansions module resolves the set of globally-enabled expansion ids (official packs default OFF, custom ON) from the library store; the Archive loads it async on mount.
- **Archive gating**: the Archive filter pipeline iterates the expansion-gated catalog (catalogFor) instead of the raw catalog; domain chips derive from the gated catalog's actual domains (base order preserved, Void domains appended), replacing the hardcoded base-9 chip list. The library hub's authoring domain quick-picks derive the same way.
- **Modal tap-catching**: the library popups (expansion form, type chooser) adopt the OverlayShell pattern — the panel is a touch-claiming container so inner taps never reach the backdrop. The expansion form's backdrop loses its dismiss handler entirely (Cancel-only), as does the standalone card editor's scrim (already Cancel-only in sheet mode). The type chooser keeps backdrop dismissal (it holds no input) but gains tap-catching and a visible Cancel.
- **Ancestry section model**: sections gain an optional boolean `feature` flag. Ancestries carry exactly two feature-flagged sections; legacy cards (no flags) resolve features to sections 0/1 via a single helper (`featureSectionIndexes`) — the ONLY place positional fallback lives. All strike/effect consumers (sheet render, creation deck, library-embed strike composer) resolve feature → section index through the helper; `ancestryEffectTrait: 1|2` keeps meaning "Nth feature by order". The editor seeds new ancestries as [description (deletable), Feature 1, Feature 2], blocks deleting feature rows, allows moving all rows, and re-labels feature rows by vertical order after every move. Bundled Void ancestries continue working unchanged via the legacy fallback.
- **Subclass class picker**: the authoring class chip list derives from the identity module's full class list (15 classes) instead of a local base-9 literal. Creation-side resolution already works once className holds a Void key.
- **Typography** (applies to the custom card renderer + forged text card; editor preview and gallery pick it up automatically since they render the same components): titles move to the loaded Archivo Black (900) at a slightly larger size; body text grows from 9 to ~10.5 with ~14 line height; body alignment switches from justify to left; paragraphs/sections render as blocks with a small (~5 design-px) gap instead of full blank lines; section names compose as bold-italic leads ("Name: ") matching official cards. FORGE_RENDER_V bumps so cached forged snapshots regenerate.
- **Expansion picker relocation**: the roster screen owns the picker; pressing New Character opens it (seeded from installed expansions + global enablement), and Continue navigates to creation with the picked ids passed as a route param. The creation screen consumes the param and no longer self-opens the picker (it keeps a fallback to the old behavior if the param is absent, e.g. deep links). Rows sort Base → official → custom. The Base row renders greyed/locked ("Always on") rather than as a live checkbox.
- **Favorites toast**: the carousel context's empty-favorites guard invokes an injected notice callback wired to the sheet's existing pushNotice toast ("Add a card to favorites!") instead of only playing the negative sfx.
- **Empty-carousel panel**: the carousel gesture entry points (gear-tap expand, edit-mode dwell) check current deck count; when zero they invoke an onEmptyOpen callback instead of expanding (no dim, no expand sfx, no gear growth). The sheet renders the "There is nothing here" panel via the OverlayShell pattern with three stacked buttons: Change category (opens a second modal listing non-empty categories from the existing ring-with-counts logic, using category meta labels/icons), Add from Catalogue (existing gear flow with the current category as override), Create Card (existing author flow with the current category as override). Programmatic expand paths get the same guard.
- **Scar effect**: a new `'scar'` EffectTarget flows through the existing modifier engine as a plain additive count (no cap; consumers clamp). The effects editor gains a "Misc" group whose "Add Scar" option emits a fixed `{ target: 'scar', delta: 1 }` and renders WITHOUT the ±N/formula/tier mode controls. The computed sheet exposes the scar count; usable hope = hope total − scars (floor 0); hope active clamps to usable on load and on every track interaction. Hope rendering greys/desaturates the rightmost N slots (dead slots draw no gold rule — the rule already spans only filled slots, and filled can never reach a scarred slot). At scars ≥ 6, a full-stage gray overlay with saturation blend mode (supported natively by RN New Architecture) desaturates the whole sheet, pointer-events none, mounted above all sheet layers. Persistence/sharing needs no migration — unknown targets default to 0 on old saves and library-card effects round-trip unvalidated.

Prototype-derived shape for the scar effect (from the effect-engine exploration):

```ts
// modifiers: EffectTarget gains 'scar'; card effect is always { target: 'scar', delta: 1 }
// sheet consumption: usableHope = max(0, hopeMax.total - sheet.scar.total); hope.active = min(active, usableHope)
```

## Testing Decisions

- Good tests exercise external behavior of pure modules, not implementation internals; UI/animation behavior is owner-device-verified (project rule: never screenshot-test motion).
- Tested modules (prior art: the existing Jest suites in src/lib — leveling.test.ts, expansions.test.ts, library-embed.test.ts, card-effects.test.ts, modifiers tests):
  - featureSectionIndexes + strike composition with re-arranged features (legacy fallback, flagged cards, struck index resolution).
  - Scar target: engine summation of multiple scar cards, usable-hope clamping in the file→sheet conversion, editor option round-trip shape.
  - Global-enabled-ids helper (official-off/custom-on defaults).
  - Level-up: an assertion that the marks considered "locked" at a tier-start level are empty (mirroring clearsTraitMarks), guarding the dialog contract.
- Data integrity suite must stay green (catalog untouched).
